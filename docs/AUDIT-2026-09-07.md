- **9 отказанных попыток** в транзакциях — восемь дописей хлебных крошек и
  одна компиляция, остановленная DLP. Работа не выполнена, след хранится.
  Известно с 2026-09-05; чинится только вручную по каждой.
- **`run/state.json` 532 КБ** при пределе 256 КиБ — две проверки слепы
  (планировщик, захват). Причина: очередь контрольных точек проекта
  `no-hands` — 215 событий с 15:13 по 18:55, 100 из них взяты в работу;
  утром было 1 127. Вывод: очередь сходит, но медленно, только при хуках
  сессий. Само по себе не ошибка; слепота проверок — да.
- **Проверка поколения отложена** по времени — та же нагрузка.
- **Счётчик «447 потерянных захватов»** на старте сессии — накопительный
  в `state.json`, а след `logs/capture-failures.jsonl` держит 15 строк, из
  них с 2026-09-06 одна (`intent_fence_lost`). Число пугает больше, чем
  значит; сбрасывается `capture_diagnostics.py --clear`.
- Линтер (`ruff --select F,E9,B006,B008`): одно замечание, в тесте
  (`tests/test_code_intelligence.py:293`, вызов в значении по умолчанию).

  вас плагин OpenCode вне репозитория; если нет — удалять вместе с тестами.

## Легаси

- **LanceDB** (`lance_store.py`, `rebuild_lance_index.py`, две ветки в
  `search_memory.py`): используется только на старом пути без дедлайна;
  путь через поколения его не трогает. Индекс построен другой моделью
  (`bge-small-en-v1.5`, а продукт — `multilingual-e5-small`). Контракт
  говорит «не удалять до свидетельства миграции»; свидетельство есть —
  поколения с векторами строятся ночью. Вывод: кандидат на удаление
  вместе с `cache/lancedb`; требует решения.
- Cursor и Antigravity — остались только ветки удаления в
  `install_control.py`, по решению об их отставке. Не легаси, а уборка.
- Слово «legacy» встречается в 37 файлах, 752 строки — в основном
  описанные пути миграции (очередь v2, транзакции v2, старые кэши).
  Отдельно не разбирал.

## Граф кода

Граф назвал две функции без вызывающих (`corpus_snapshot._require_monotonic`,
`code_graph._valid_monotonic_deadline`); `grep` показывает по одному вызову
у каждой. Это пробел покрытия индекса, не мёртвый код — учитывать при
следующих поисках мёртвого кода.

одинаковой работе).
