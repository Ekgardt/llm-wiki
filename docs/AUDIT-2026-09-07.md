# Аудит: ошибки, неподключённое, легаси — 2026-09-07 (вечер)

Проверено графом кода (codebase-memory-mcp), линтером, поиском ссылок по
всем файлам репозитория и `doctor` на живом хранилище. Факты, выводы и
предположения разделены.

## Ошибки (живое хранилище, `doctor`)

- **9 отказанных попыток** в транзакциях — восемь дописей хлебных крошек и
  одна компиляция, остановленная DLP. Работа не выполнена, след хранится.
  Известно с 2026-09-05; чинится только вручную по каждой.
- **`run/state.json` 532 КБ** при пределе 256 КиБ — две проверки слепы
  (планировщик, захват). Причина: очередь контрольных точек проекта
  `no-hands` — 215 событий с 15:13 по 18:55, 100 из них взяты в работу;
  утром было 1 127. Вывод: очередь сходит, но медленно, только при хуках
  сессий. Само по себе не ошибка; слепота проверок — да.
- **Проверка поколения отложена** по времени — та же нагрузка.
- **Счётчик «447 потерянных захватов»** на старте сессии — накопительный
  в `state.json`, а след `logs/capture-failures.jsonl` держит 15 строк, из
  них с 2026-09-06 одна (`intent_fence_lost`). Число пугает больше, чем
  значит; сбрасывается `capture_diagnostics.py --clear`.
- Линтер (`ruff --select F,E9,B006,B008`): одно замечание, в тесте
  (`tests/test_code_intelligence.py:293`, вызов в значении по умолчанию).

  выводом конца действия; ни один модуль его не импортирует. Сегодня туда
  добавлен вес надёжности. Подключение к пути ответа — отдельное
  архитектурное решение (нужно ваше «да»).
- **`retrieval._INTENT_PATTERNS`** — пять английских шаблонов выбора
  профиля; судьба по замеру (прогон с принудительным HYBRID).
- **`scripts/heartbeat_record.py`** — помощник плагина OpenCode; плагина
  в `integrations/` нет (только claude-code и codex), из кода продукта его
  никто не вызывает, но семь тестов в `tests/test_plugin_helpers.py` его
  проверяют. Пробовал удалить — тесты упали, вернул. Не знаю, стоит ли у
  вас плагин OpenCode вне репозитория; если нет — удалять вместе с тестами.

## Легаси

- **LanceDB** (`lance_store.py`, `rebuild_lance_index.py`, две ветки в
  `search_memory.py`): используется только на старом пути без дедлайна;
  путь через поколения его не трогает. Индекс построен другой моделью
  (`bge-small-en-v1.5`, а продукт — `multilingual-e5-small`). Контракт
  говорит «не удалять до свидетельства миграции»; свидетельство есть —
  поколения с векторами строятся ночью. Вывод: кандидат на удаление
  вместе с `cache/lancedb`; требует решения.
- Cursor и Antigravity — остались только ветки удаления в
  `install_control.py`, по решению об их отставке. Не легаси, а уборка.
- Слово «legacy» встречается в 37 файлах, 752 строки — в основном
  описанные пути миграции (очередь v2, транзакции v2, старые кэши).
  Отдельно не разбирал.

## Граф кода

Граф назвал две функции без вызывающих (`corpus_snapshot._require_monotonic`,
`code_graph._valid_monotonic_deadline`); `grep` показывает по одному вызову
у каждой. Это пробел покрытия индекса, не мёртвый код — учитывать при
следующих поисках мёртвого кода.

## Что сделано

- Стенд делит ядра между рабочими процессами
  (`OMP_NUM_THREADS = ядра // параллельность`, замер: 28,5 → 15,6 с).
- **LanceDB удалён** целиком: модуль, скрипт перестройки, две ветки поиска,
  поле `lance_distance`, зависимость, кэш, тесты только про него. Проверил:
  таблица на живом хранилище никогда не строилась, путь достижим только из
  старого поиска без дедлайна, индекс был под другую модель. Решение:
  `knowledge/notes/retire-lancedb-decision.md`.
- **`bitemporal_claims` не подключаю**: на живом хранилище 61 утверждение,
  чтение закрыло бы 0 из 61; стенд утверждений не видит. Остаётся
  библиотекой для конвейера противоречий.
  `docs/research/2026-09-07-bitemporal-claims-stay-a-library.md`.
- **Очередь `no-hands` слита** (215 → 0), `run/state.json` 532 → 53 КБ,
  слепота двух проверок `doctor` снята. Ночной слив 7 сентября сообщал
  «2 проекта упали» — это была ошибка перепривязки, починенная днём.
- Плагин OpenCode есть на другой машине — `heartbeat_record.py` остаётся,
  записано в `integrations/README.md`; его `main` приведён к пределу
  сложности.
- Замечание линтера в тесте убрано; пять старых тестов в тронутых файлах
  приведены к пределу сложности; `benchmark/run_benchmark.py` переписан
