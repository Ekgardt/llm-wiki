# Что теперь работает, что нет, и что осталось

Отчёт на 2026-09-12, после слияния PR 31. Написан для чтения человеком:
сначала — что вы можете делать прямо сейчас, потом — что не сделано и почему,
потом — оставшиеся задачи и проблемы.

---

## 1. Что вы можете делать прямо сейчас

Ниже — вопросы, которые система теперь отвечает по коду, и чем именно. Все
ответы идут через один инструмент `get_architecture`; ничего доустанавливать
для Python не нужно.

**«Кто вызывает эту функцию? Что вызывает она?»**
Ответ приходит по графу за десятые доли секунды, с глубиной до восьми шагов.
Работает для любого проиндексированного языка; для Python, TypeScript, Go и
Rust ответ подтверждается языковым сервером, а не совпадением имён.

**«Где определение и как выглядит этот код?»**
Точное определение и вырезка исходника по имени символа, с номерами строк.

**«Что передаётся в эту функцию при вызове?»** *(новое)*
Режим `data_flow`: по каждому разрешённому вызову система называет, какое имя
у вызывающего ложится на какой параметр вызываемого — шаг за шагом, до восьми
шагов. Ответ сам пишет о себе, что это связывание аргументов, а не полный
анализ потоков данных: так никто не прочитает в нём больше, чем там есть.

**«Кто обслуживает этот HTTP-запрос?»** *(новое)*
Режим `cross_service`: клиентский вызов с явным путём находит маршрут и
переходит в функцию-обработчик. Если маршрут обслуживает другой репозиторий —
система находит его среди маршрутов остальных проиндексированных рабочих
копий и называет обработчик, файл и репозиторий, не заходя внутрь чужой
генерации.

**«Какие тесты покрывают эту функцию?»**
Обычный вопрос «кто вызывает», ответ включает тестовые файлы.

**«Что сломается, если я поменяю это?»**
Режим `impact`: функции, которые вызывают, импортируют или наследуют
изменённый символ, в пределах восьми шагов, плюс затронутые страницы памяти.

**«Можно ли верить ответу „ссылок нет“?»**
Режим `coverage`: по каждому файлу видно, что индексатор смог прочитать, а
где были синтаксические ошибки. Отрицательный ответ теперь проверяем.

**Подсказки без запроса.** Когда агент ищет по тексту (`Grep`, `rg`) слово,
которое в проиндексированном репозитории является символом, он получает
короткую подсказку: три определения с путями и степенью связности, плюс имя
инструмента, который ответит точно. Работает в Claude Code, Codex и OpenCode.

**Рабочие копии сами появляются и исчезают.** Индекс новой ветки создаётся
без ручных действий, а индекс удалённой копии убирается на следующем проходе
обслуживания.

**Точная навигация по четырём языкам.** Python — из коробки. TypeScript, Go и
Rust — по одной явной команде на язык:

```
uv run python scripts/install_language_server.py --profile typescript   --state-root <state-root>
uv run python scripts/install_language_server.py --profile gopls        --state-root <state-root>
uv run python scripts/install_language_server.py --profile rust-analyzer --state-root <state-root>
```

Цена установки, измеренная здесь: Go — 44 с, 324 МБ на диске; Rust — 49 с,
137 МБ загрузки и 701 МБ на диске. Ответы после прогрева: 0,10 с. Пока язык
не установлен, вопросы по нему отвечаются по структуре кода, как и раньше, и
ответ это честно говорит.

## 2. Что сделано за эти сутки

- **Связывание аргументов и HTTP-граница** — два новых режима выше. Извлечение
  кода теперь пишет по каждому разрешённому вызову пары «аргумент →
  параметр» и связывает клиентские вызовы с маршрутами.
- **Маршруты между репозиториями** — файл подсказок каждой рабочей копии
  получил таблицу маршрутов, и кросс-сервисный вопрос находит ответ в соседнем
  репозитории.
- **Точная навигация для Go** — языковой сервер собирается из исходников
  пинованным компилятором, потому что готового бинаря авторы не публикуют.
- **Точная навигация для Rust** — пять архивов одного выпуска ставятся как один
  тулчейн; без компиляции.
- **Набор задач для сравнения с codebase-memory-mcp расширен** — прежние 13
  задач плюс две про связывание аргументов и одна про тесты, и отдельный
  кросс-сервисный набор на фикстуре из двух репозиториев. Эталонные ответы
  выверены по коду вручную.
- **Три настоящие причины красного CI найдены и устранены**: повтор записи
  поверх уже завершённой транзакции считался провалом и уходил в карантин;
  тесты гонки добавлений брали срок из числа в коде вместо общего места для
  медленных машин; один тест требовал от общей доски больше, чем она обещает.
- **Правило сложности в продуктовом коде выполняется полностью**: в `scripts/`
  и `benchmark/` ноль нарушений.

## 3. Что не сделано, и почему

- **Прогон сравнения с codebase-memory-mcp не выполнен.** Набор задач готов,
  чисел нет: прогоны выполняются только с вашего прямого разрешения.
- **Отдельный язык запросов к графу не делался.** Он не нужен: типизированный
  запрос (`mode=query`) уже отвечает на вопросы, для которых нет готового
  режима, и делает это без языка, в который можно что-то подставить.
- **Языковые серверы не установлены на живом хранилище.** Установка — ручное
  действие оператора по контракту; я её здесь не выполнял.
- **Массовая чистка тестов под правило сложности не делалась.** Причина ниже.

## 4. Оставшиеся задачи

1. **Прогон стенда** (`benchmark/code-parity-v2.json` и кросс-сервисный набор).
   Нужно ваше разрешение. После прогона появятся честные числа: правильность,
   время, токены — по каждой задаче, для нас и для codebase-memory-mcp.
2. **Правило сложности в тестах: 1065 нарушений в 331 файле.** Основная
   причина — проверка считает каждый `assert` ветвлением, поэтому тест с
   пятью проверками уже «слишком сложный». Моё предложение: не переписывать
   всё разом, а приводить файл в порядок, когда мы его и так трогаем. Решение
   за вами.
3. **Установить языковые серверы на живом хранилище**, если хотите точную
   навигацию по TypeScript, Go и Rust здесь, а не только в тестах.
4. **Закрыть issue #24.** Все критерии, кроме прогона из пункта 1, выполнены.

## 5. Оставшиеся проблемы

- **Хранилище: «ослаблено» (degraded), два пункта.** Первый: две ссылки на
  дневник больше не сходятся по отпечатку — дневник дописали после того, как
  страница была скомпилирована. Лечится перекомпиляцией этого дня или
  `doctor --repair`; я не запускал ни то, ни другое, потому что обслуживание
  живого хранилища за мной не закреплено. Второй: счётчик пяти потерянных
  захватов от 11 сентября; он обнуляется командой `capture_diagnostics
  --clear` и сам по себе ничего не ломает.
- **Ночное обслуживание снова проходит.** Проход 12 сентября завершился без
  сбоев, генерация собралась за 85 секунд. До этого оно падало с 7 сентября —
  причины исправлены и вошли в main.
- **Карантин проверен, потерь нет** (исправление от 12 сентября: числа «102
  спорных утверждения» в хранилище нет). В карантине ноль утверждений и 117
  записей транзакций: 114 отказов по предусловию и 3 отказа границы DLP. Для
  116 из 117 сразу после отказа есть закреплённая запись в тот же файл —
  текст дописала следующая попытка. Подробности и измерения:
  `docs/research/2026-09-12-what-the-quarantine-actually-holds.md`.
- **Известный компромисс общей доски.** Если запись успела закрепиться, но
  сразу после этого упала, а поток в тот момент не читался, претензия
  освобождается и остаётся видимая «активная» задача, которую никто не
  завершит. Это выбрано сознательно и описано в коде: альтернатива — молча
  блокировать ресурс до истечения аренды. Теперь это же утверждает и тест.
- **Первый запрос в новом процессе отвечает по структуре.** Языковой сервер
  ещё читает проект; со второго запроса ответ точный. Это корректная
  деградация, а не ошибка, но её видно.
- **Windows медленнее всех.** Два падения этой ночи были только там: разные
  разделители в путях и понятие «абсолютный путь». Исправлено, но при
  добавлении тестов это стоит держать в голове.
