# Queue schema definitions

`llm_wiki.queue_schema` owns 22 table, 5 index and 35 trigger definitions, in
existing order and with unchanged SQL. It has no imports or database side effects.
The generated immutable triggers remain generated by the same expression.

`queue_core` imports the identical tuples. It retains schema digest composition,
operational database contracts, migration statements, repair, adoption and SQL
execution. No schema version, constraint or migration is added by this extraction.
Existing tuple names remain available in queue_core as direct aliases for
compatibility; there is only one definition. Integration tests check those aliases
and both base/compile schema fingerprints against the pre-extraction baseline.

Own tests cover exact ordered definition hashes, real SQLite catalog construction,
constraint failures, immutable history, authorized deletion and isolated import.
The baseline fixture stores hashes, not another copy of the SQL. Mutation checks
prove that changing or removing a definition is detected. Import isolation is
verified in a fresh interpreter, without the executor or durability layer.

Run `uv run pytest tests/modules/queue_schema -q -s`. The context manifest counts
all own tests, fixtures, source, documentation and required instructions against
100000 o200k_base tokens. Cross-boundary migration/adoption/corruption and compile
admission tests additionally qualify integration; they intentionally load the
executor and are not an isolated module maintenance packet.

Evidence: ../research/2026-11-02-queue-schema-boundary.md. This step does not finish
modularizing the queue and is not a rollout to the installed vault.
