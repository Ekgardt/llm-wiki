# Corpus membership policy

This internal pure owner holds six existing immutable values moved intact from
`corpus_snapshot`: PROJECT_FILES, APPROVED_CODE_ROOTS, VAULT_CODE_ROOTS,
ARCHIVE_DIRECTORIES, GENERATED_DIRECTORIES and VAULT_SKIP_DIRECTORIES. The values,
types and original explanatory comments are preserved. It imports no product
runtime or collector. The collector retains public aliases, its existing vault
root annotation and every traversal, validation and capture algorithm.

The distinction matters: code-shaped paths used in provenance are not the code
roots indexed by a vault's memory generation. APPROVED_CODE_ROOTS retains the
seven existing product directory names. VAULT_CODE_ROOTS remains empty; code is
indexed separately by repository. PROJECT_FILES retains state.md and context.md,
not the journal. Generated bytecode is excluded across repositories, while
_template/gaps/raw-sources are the vault's vocabulary. Archive names and the
caller's include_archives behavior remain unchanged. Foreign repositories still
supply their own code-root names to the collector's existing validation.

`provenance._code_roots` reads its same constant from this policy owner. It no
longer imports a collector to obtain immutable membership data. Collector users,
including doctor and query_memory, keep their existing aliases. Import paths at
the old public boundary, function defaults and allowed-path behavior remain.
The aliases are necessary compatibility, not a second implementation or a second
set of values. No live generation is rebuilt or installed by this transfer.

## Evidence and alternatives — 2026-11-03

Before the change, provenance's full static source closure was 183 files /
1424240 tokens; page_facts reached 185 / 1425926. The actual dependency was the
single constant import in provenance._code_roots. Source-only counts are not
complete packet measurements or full-cycle LLM cost savings.

The transfer preserves all six declaration ASTs and all 221 existing collector
function/class definitions. The provenance AST changes only the constant's
import source. Runtime checks confirm the same objects at all old aliases, the
same public annotation and the same collector default. After transfer, static
source closure is 3 files / 3092 tokens for provenance and 6 / 5262 for page_facts.
The real collector/foreign-root/trust tests passed 129 cases with 3 existing
platform skips. These source-closure reductions do not waive complete packet
measurement or prove whole-task LLM savings.

Copying the values would create competing policy authorities. Hiding the import
would preserve the dependency. Introducing runtime interfaces for immutable
data would add machinery. The chosen boundary keeps one concrete data owner and
existing public aliases under the approved autonomous completion plan.

Three independent primary sources reviewed on this date:
[Fowler bounded contexts](https://martinfowler.com/bliki/BoundedContext.html),
[Import Linter dependency contracts](https://import-linter.readthedocs.io/en/stable/contract_types/),
and [PEP 544](https://peps.python.org/pep-0544/). They support explicit cohesive
boundaries and optional structural typing; they do not prove behavior equivalence.
The proof here is exact value/definition transfer plus real integration tests.
Python 3.14 and existing standard-library types are unchanged.

Historical corpus policy research from 2026-08-29, 2026-09-10 and 2026-09-23 is
included in full. Existing foreign-root/trust/authority baseline: 18 tests passed.
Built-in graph `generation-18e4987440565d6f-a17b1fa8`, source and callers were
inspected before edits. Run the pure owner tests, original corpus/foreign-root
and retrieval integration tests, source/ownership gates and every packet budget.
The complete packet retains the unchanged 100000 o200k_base ceiling. Broad caller
integration ownership remains part of unfinished whole-project decomposition.
