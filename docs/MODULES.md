### Approved completion mandate (2026-11-02)

`docs/research/2026-11-02-decomposition-completion-plan.md`, including refinement
of internal boundaries within its responsibility families. Each boundary is
documented and qualified before acceptance. Full maintenance packets remain
limited to 100000 tokens. Since 2026-11-11 every tracked file is owned by a module
or is pinned vendored data: the tokenizer vocabulary under `tests/data/tiktoken/`,
which no packet can hold, is covered only while its name and SHA-256 match
`PINNED_VOCABULARIES` and no module claims it
([decision](research/2026-11-11-the-tokenizer-vocabulary-is-pinned-data.md)).
`python -m tests.module_ownership --check-complete` is the gate, and
`tests/test_module_registry_integration.py::test_every_tracked_file_belongs_to_a_module`
fails in CI on a tracked file that is neither.

### Unified Python runtime

The supported runtime is Python 3.14.x for installation, development and CI, as
approved on 2026-11-03. Metadata excludes 3.15 until required binary dependencies
provide compatible builds; reassess that boundary when upstream support arrives.
A project interpreter pin selects 3.14, and installers select that series for
bootstrap and environment creation. Linux, Windows and macOS remain tested; the
current native macOS lane is ARM64. Intel macOS full dependencies are not qualified:
both the previous and updated ONNX Runtime locks lack its binary distribution.
See [the approved plan](research/2026-11-03-python314-unified-runtime-proposal.md).

### Native replacement test support

fixture path, allowing the original identity guard assertions to run after a real
replacement. Production descriptor sharing and permission checks remain intact;
a separate native test checks ordinary open-file replacement refusal. This helper
remains an explicit integration dependency, not a qualified leaf module.

A packet holds its own code, its tests and, for a dependency it declares under
`qualified_dependencies`, a description derived from the provider's real code
(`tests/module_interface.py`, `tests/module_interface_render.py`,
`tests/module_qualification.py`). A description that differs from the code, a use
that reaches around public names, or a dependency with no real test across it fails
measurement. `python -m tests.module_qualification_refresh` rewrites a stale digest.

a name both roots carry means neither. A module loaded by its file path has no
import name to follow, so it is always held whole.
