# Canonical qualification contract versus repeated pilot history

Date: 2026-11-03. Investigation under the approved decomposition mandate;
implemented after the separate queue byte-bound correction.

The three historical pilot documents are included in every current manifest:
module-boundaries-and-token-budget (6602 o200k_base), module-boundaries-validation
(4849), formats-module-pilot (4201): 15652 tokens per packet before framing.
All three were read fully, including the truncated excerpt of the pilot re-read
separately. They mix current invariants with superseded candidate maps, old test
results, specific receipt-format history, operational observations and measurements.
Those historical files must remain intact and available. A lookup contract alone
must not replace context that is actually necessary for an owner's maintenance.

Implemented change: keep the complete three-file history in the context-tooling
packet and the formats packet where the pilot is directly relevant. Give the two
cross-project research documents a tooling owner and the format pilot its format
owner. Every packet gets the full current canonical qualification guide, not only
a link. Keep its precise owner research, full STRUCTURE, AGENTS/CLAUDE, nine laws,
source/dependency guides, tests/support/fixtures and the exact measurement code.
Other packets omit only the unrelated historical pilot narrative. No repository
file is deleted, summarized in place, minified, or silently classified as complete.

## Normative coverage that must be retained before any change

- One product/installation, unchanged public commands, schemas, env/runtime roots,
  authority, SQLite/fencing/security and recovery: full AGENTS + STRUCTURE.
- Nine laws, permission boundaries, evidence before claims, CCN<=5, no arbitrary
  bounds or duplicate implementations: full development-laws and operating rules.
- <=100000 for ownership and complete working packet; o200k_base encode_ordinary,
  actual framing, exact duplicate codec, byte/path reconstruction and complete
  tracked-file ownership: canonical tooling guide plus unchanged executable gates.
- Tests, helpers, schemas and fixtures cost context; mixed integration scenarios
  remain qualified and separately accounted, never mocked away for a small packet:
  canonical guide plus the strengthened source/test/bootstrap/guide closure guards.
- Semantic responsibilities, no quota of modules, no automatic interfaces/bus or
  separate services; explicit stable aliases and public pickle identity; remove
  duplicate bodies and qualify real consumers/patch sites: canonical guide and
  precise per-owner research/contracts.
- Static graphs/imports are incomplete; check dynamic calls, resources, config,
  subprocess and side effects. Bounds and readiness claims require evidence:
  canonical guide, current owner tests and platform qualification records.
- Tokenizer/file totals are neither provider billing nor a full task-cycle gain.
  Paired quality-equivalent tasks must include retries, cache accounting without
  double count, all input/output, latency, resources and operator work. No preset
  sample quota or promised percentage: canonical guide plus retained research.
- Python >=3.10 remains despite upstream support status; platform skips are not
  passes; no live installation without separate owner permission: canonical guide
  and full instructions. Deployment/release contracts remain in AGENTS/STRUCTURE.

Before implementation, test that every packet carries the canonical guide; make
omission fail. Validate that no other source/research/fixture disappears, prove
historical file bytes unchanged, retain format/tooling history in full, rerun
ownership/closure/complexity and actual bundle reconstruction. Report exact new
packet sizes, separately from unchanged unique repository history. Do not claim
LLM task savings without the required paired evidence.

## Current primary sources / alternatives

Three independent publishers checked 2026-11-03:
- Diataxis distinguishes explanatory context from operational reference, while
  explicitly treating explanation as necessary knowledge, not disposable text.
  https://diataxis.fr/explanation/
- Fowler's Bounded Context explains explicit responsibilities and relationships;
  it does not prescribe module counts or prove an empirical token reduction.
  https://martinfowler.com/bliki/BoundedContext.html
- Import Linter's explicit contracts support retaining enforceable boundaries,
  instead of relying on a shorter document's assertion of completeness.
  https://import-linter.readthedocs.io/en/stable/contract_types/

Rejected: delete history, replace required source by summaries, omit user laws,
loosen import/ownership gates, or treat a compressed bundle as a real task-cost
benchmark. The proposed change selects relevant context and preserves history;
it does not reduce the unique tracked source bytes by itself.
