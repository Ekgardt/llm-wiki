# Native citations can use the existing source choice protocol

Research date: 2026-10-09. Installed 0ac0801f provides verified native event addresses, but the actual full compiler still rejected three attempts for incomplete native quotes and other attempts for malformed evidence objects. Logs and complete protected requests/responses remain in `logs/step7-full-cycle-native-address-medium-20261009.*`. This proves that supplying addresses alone is insufficient. The running baseline is left unchanged.

Candidate design: extend the existing transient `{source_line, claim}` choice format to verified native user lines. A locally assigned output ID selects exactly one displayed, protected user line in an already verified selected physical container. Expand it locally into the existing native evidence object, then execute the unchanged timestamp, line, container, provenance and source-hash validators. Never infer an address from a returned partial quote. Retain the manual native evidence format for compatibility. No stored schema, runtime directory, environment variable or MCP tool is introduced.

Choices must be drawn only from canonically verified selected native source projections and aligned DLP-protected rows. Untrusted examples and metadata cannot introduce choices. A protected complete line may be offered; hidden or unparsable rows cannot. Output IDs are opaque, distinct from both legacy LF locators and zero-based native user-line locators. Compact ranges may be used only where IDs and line indices advance together in one event. The planner must count the actual expanded prompt and choice schema. The draft cache program must change.

Alternatives: additional instructions still require the model to reproduce a long string and have already failed on this installed run; increasing retries repeats the same cost; accepting prefixes or clamping indices weakens evidence authority; a new citation schema adds migration work. Existing locally resolved choices provide a bounded exact correspondence without changing the evidence contract. Extra address-table bytes and preparation CPU remain costs, to be measured against retries and useful output; no savings are claimed in advance.

Independent primary sources inspected:

- W3C PROV-DM, https://www.w3.org/TR/prov-dm/ : provenance and derivation belong to identified source entities. This is a stable 2013 Recommendation, not a newly released implementation.
- OWASP Input Validation, https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html : syntactic and semantic validation are separate; both remain enforced locally.
- JSON Schema enumerated values, https://json-schema.org/understanding-json-schema/reference/enum : an enum expresses an offered finite choice. Its size is the actual selected source set, not an arbitrary limit. The existing validator and source-ID schema already support this vocabulary; no dependency version changes.

Qualification pending: causal RED for a native choice, exact complete-container binding, multi-line and Unicode inputs, forged/missing source and IDs, DLP visibility, unchanged ordinary source choices, real rejected-packet replay, planner accounting, complexity, related regression, real paired model cost and installed full-cycle completion.

## Repeated sizing work

The installed live process was sampled without injecting code or reading locals. The 20-second py-spy sample had 80 usable stacks and 19 read errors. It identifies repeated entry-overlap scans and prompt redaction during optional-context sizing; it does not establish whole-cycle percentages. A separate saved protected request of 252,948 characters took 0.0332 seconds in named-value redaction alone. Changing the shared credential detector is not justified by that measurement and is outside this change.

Reuse only pure entry-overlap tuples inside the existing finite sizing scope, keyed by the exact frozen DailySnapshot object and retaining that object. Return fresh lists. A replacement object, even with the same logical source key, misses the cache. Ordinary callers outside sizing recompute. This is not a cached approval: final source and hash validation remains independent. The canonical native projection produced by the current size measurement can similarly avoid immediate duplicate reconstruction, but only for exactly retained source and part identities; changed selections and final authority checks still reconstruct independently. No global LRU, lifetime extension, arbitrary capacity limit or additional storage is introduced.

Additional primary source checked on 2026-10-09: Python 3.10 dataclasses documentation, https://docs.python.org/3.10/library/dataclasses.html , defines frozen-field behavior and replacement objects. Python, W3C and OWASP provide three independent primary sources for the immutable-data and separate-authority design. Alternatives are continuing repeated pure scans, changing protected-read authority caches, or memoizing whole growing prompt projections. The last two risk stale approval or accumulating large content; this design retains only the finite input metadata and one current canonical projection.
