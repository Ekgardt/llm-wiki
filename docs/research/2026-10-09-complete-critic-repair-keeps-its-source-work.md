# Complete critic repair keeps its source work

Date: 2026-10-09. Status: candidate qualification; this document does not close audit point 7.

A normal installed compiler pass prepared 219 groups from six closed days. In three observed groups, a complete source draft fit, but its next correction was refused before dispatch. The source packing budget had grown only to the measured source minimum. Validated critic feedback then added every reviewed operation, including passed operations, their bound citations and claims. Raising correction admission to the selected model's verified window alone was insufficient.

The installed Codex CLI 0.160.0 resolved the selected model's usable planning window to 258,400 tokens. Local counting without a qualified tokenizer remains an estimate of one token per UTF-8 byte, not an exact model count or a tokenizer-independent bound. The recorded source requests occupied 244,833, 246,500 and 243,778 local bytes; the provider reported 83,997, 96,146 and 88,998 input tokens. Those quantities have different boundaries and must not be represented as exact tokenizer comparisons. The complete locally bound feedback was 112,151, 16,061 and 50,503 bytes. Native `debug prompt-input` returns prompt messages, not a token-count endpoint. A paid API counting route or an unsupported tokenizer alias is not introduced.

## Chosen correction

The initial source target remains unchanged. A correction may use the same selected Codex model's verified planning window; unknown, mismatched and other-provider capacity cannot manufacture a larger window. Preflight and actual dispatch use the same budget and unchanged output reservation and slack.

When that complete correction still does not fit, the compiler can repartition the independent source work at existing verified unit boundaries. It tries cuts nearest equal physical byte size. Each child preserves its whole original parts, all selected context, targets and vault files. The exact original reviewed operations and matching reviews are assigned once to a child only when the existing citation validator can bind every citation there. An operation spanning the cut refuses that cut; indivisible work retains its capacity failure. A child carrying reviewed work cannot turn an empty rewrite into no-content authority.

Every child has fewer source units than its parent. That strict decrease supplies termination; no new retry count, source size ceiling, runtime directory, database schema, environment contract or provider is added. Each child refreshes current context and fails if selected context disappears. A failed child remains recorded while its independent sibling can proceed. The original provider failure and already spent calls remain visible; repartition is not an accepted result or a receipt. Publication continues through the existing validated transaction and receipt path.

## Evidence and limits

Five initial causal guards failed before implementation. Related checks passed on Python 3.10 and 3.14. The actual callable analysis includes changed functions, nested functions and lambdas and retains the nine-law thresholds. Original regression assertions remain in place.

A read-only replay reconstructed all three recorded source requests byte for byte. The groups of 12, 15 and 13 complete units partitioned into 9+3, 7+8 and 7+6. All six correction prompts fit the same verified window. The union of original physical parts, full reviewed operation records and review records was exact. This proves capacity and preservation on the observed refusals; it does not prove a model's correction quality or successful publication.

The interrupted normal installed pass took 1,308.678 seconds and made ten completed provider calls: 402,803 reported input tokens and 12,031 output tokens. Four groups finished and one was interrupted; three pages were published. All of those costs count. The whole closed-day pass, subsequent retrieval, normal nightly, complete health checks and actual platform CI still require completion. Existing validation retry and output/slack policy are unchanged; this change does not claim those policies have newly acquired a complete capacity basis.

## Research and alternatives

The research was checked on 2026-10-09 against independent primary providers: [OpenAI token counting](https://developers.openai.com/api/docs/guides/token-counting), [Google token accounting](https://ai.google.dev/gemini-api/docs/tokens), and [Anthropic token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting). They distinguish token counts from character estimates and account for complete input structure. Provider-specific token APIs do not establish a subscription-backed Codex counter. The actual local model advertisement and pinned CLI are the authority for the selected planning window.

Increasing an unverified limit, erasing feedback, shortening required source/context, dropping passed proposals and accepting an empty rewrite were rejected. Repartition retains the existing source and validation contracts at the cost of additional measured calls when a source group cannot accommodate correction. Whole-cycle useful output and total cost must determine whether that tradeoff succeeds.
