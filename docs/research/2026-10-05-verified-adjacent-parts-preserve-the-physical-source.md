# Verified adjacent parts preserve the physical source

Research date: 2026-10-05. The correctness change is installed. The complete model/nightly cycle remains unqualified, and the audit remains open.

Before this change, the compiler ended a batch when it reached a second part of the same daily source, even when that part was an immediately adjacent, verified slice of the same immutable original. This restriction was separate from the caller's context budget. Removing it must preserve original bytes, physical source identities, citation bounds, complete native frames, and receipt manifests.

This replaces the batching restriction described in the [2026-09-25 historical report](2026-09-25-one-part-of-a-day-per-batch.md). That report is retained as evidence of the original dropped-text defect. Unverified same-day joins and opaque custom measures still retain the conservative restriction; no historical receipts are upgraded automatically.

Three independent primary references were checked on the research date: [Python 3.10.22 immutable bytes](https://docs.python.org/3.10/library/stdtypes.html#bytes-objects), [Git's content-addressed objects](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects), and [SQLite isolation](https://www.sqlite.org/isolation.html). They support distinguishing immutable content identity from changing external state; none proves the performance or correctness of this implementation. Those require local evidence.

The candidate admits only contiguous members of the actual original partition. It checks original source digest and bytes, part ordinal/count, exact bounds, slice bytes and digest, and coverage of native physical frames. It retains the caller's context budget and fresh external breadcrumb verification. Arbitrary measures and foreign/replaced input owners keep the conservative path. No stored format, runtime path, environment contract, dependency, or authority changes.

Pure partition facts may belong to the exact captured input object; they are not cached external verification results. A measurement-owned lookup gathers requested parts in their original order and reads their actual bytes. Lost or foreign ownership falls back to ordinary computation. A global proof cache was rejected because filesystem and transaction authority can change. A term-postings optimization was tested and removed because real-corpus cost did not justify it.

The same captured input contained 3340 parts and 1517 sources. The installed implementation produced 3320 prospective batches; the candidate produced 3304. Independent verification checked every original and slice digest, all parts, concatenated daily content, context bytes, canonical receipt manifests, and 1139 decoded native frames. No model calls or publications occurred in this comparison.

Observed packing wall time was 128.254 s versus 126.995 s, but candidate CPU user time increased by 7.859 s. Peak measured RSS decreased by 12848 KiB. These sequential profiled measurements ran on a shared machine. They do not establish a speedup or full-cycle token efficiency. Sixteen fewer prospective batches are only a 0.48% reduction; provider calls, answer quality, publication cost, and the complete nightly cycle still need qualification.

The diagnostic operator initially ran out of disk while duplicating frame descriptions. Its incomplete result was preserved and explicitly refused. The final comparison stores content by digest and independently checks the complete streams. An initial verifier used the wrong physical indentation; that failure was retained and the corrected diagnostic was rerun without changing product bytes or artifacts.
