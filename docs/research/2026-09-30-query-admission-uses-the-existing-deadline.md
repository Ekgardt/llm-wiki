# Query admission uses the existing deadline

Research date: 2026-09-30. Recall and decision retrieval refused a 9225-character valid string at the MCP boundary because of an unmeasured 8192-character constant. The underlying real lexical search on an isolated vault returned its evidence page in 1.313 seconds under a 30-second caller deadline. This measures that case, not universal performance or semantic quality for arbitrary large prompts.

The MCP boundary now validates the string type and forwards the whole query under the existing operation deadline. Optional decision queries still accept None and retain their existing default. Both JSON schemas drop the unexplained maxLength; filename bounds, result budgets, evidence/hash validation, DLP, provider context limits and fallback reporting remain enforced. No runtime path, operator setting or environment contract is introduced.

Three independent primary sources checked today: [MCP tools specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) defines schema and tool validation without imposing an 8192-character query limit; [JSON Schema string constraints](https://json-schema.org/understanding-json-schema/reference/string) makes maxLength optional; [OWASP resource consumption](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/) recommends resource controls grounded in actual operations. These do not prove arbitrary large inputs harmless; existing deadline and provider/resource controls continue to apply.

Alternatives: invent a larger cutoff, or make the old number configurable without evidence, would preserve an unjustified refusal. Removing all downstream safety/resource bounds would exceed this finding. Removing this redundant admission rule retains type safety and preserves existing bounded execution. Two regressions fail on the old recall/decision entry points and verify full query forwarding and caller deadline propagation. Separate wrong-type regressions preserve refusal. End-to-end quality and token efficiency for all possible long queries are not claimed; the change itself adds no model calls.

Qualification: query-phase related group 466 passed, 1 skipped; final MCP/shared-page group 378 passed, 2 skipped; complexity/branch gates 37 passed; exact public source checks 134 passed, 3 skipped and Gitleaks passed. All 12 changed functions measured CCN <=3 with branch/nesting checks. A fresh process using installed source retrieved two chunks for the 9225-character query and read/hashed the complete 4194369-byte page in 10.233 seconds, including existing optional local-model startup; no paid/generative provider call was made. Failed old-limit tests and a corrected test expectation for the public response envelope remain in the qualification logs.
