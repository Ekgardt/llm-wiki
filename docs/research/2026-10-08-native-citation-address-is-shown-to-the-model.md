# Native citation addresses belong in the verified projection

Research date: 2026-10-08. Python 3.10 remains supported. An installed compile returned a native citation with a timestamp different from the verified daily heading. Inspection confirms that the model-facing JSON has the event identity and user lines, but omits the canonical timestamp required by the evidence validator. The original event envelope does not supply that timestamp either. The complete prompt does retain the daily heading and its canonical time; inspection of the recorded real request confirms this. The change makes each verified event's citation address explicit rather than requiring association with a separate heading. It does not establish that the absent JSON field caused every rejected model response.

Expose the daily date, verified frame timestamp and zero-based user line indices alongside the existing projection. Derive them from the already verified physical frame. Preserve the existing event identity and string-valued user lines, immutable source hashes, full-container coverage, exact timestamp, line bounds and whole-line quote validation. Instruct the model to copy those addresses. Version the draft program so resolved plans remain bound to the actual prompt. This changes transient prompt metadata, not the citation schema, runtime layout, environment contracts or stored source.

Alternatives: infer the timestamp from model output, ignore mismatches or clamp indices would weaken evidence validation; retaining separate headings still requires the model to associate their times with the correct event; replacing the existing native citation protocol adds unnecessary migration and compatibility work. Explicit addresses add prompt bytes proportional to the number of lines. Full-cycle cost and useful output must be measured before claiming token savings.

Independent primary references checked on this date:

- W3C PROV-DM explains entities, their derivation and provenance: https://www.w3.org/TR/prov-dm/ . This is a stable 2013 Recommendation, not a claim about a newly released framework.
- OWASP distinguishes syntactic and semantic validation: https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html . Both remain enforced by the existing local validator.
- Python 3.10 documents explicit date and time formatting: https://docs.python.org/3.10/library/datetime.html#datetime.datetime.strftime . The implementation preserves the already verified source timestamp rather than generating a new clock value.

Qualification requires a source-to-projection-to-citation round trip, rejection of forged times and line indices, the related native source and transaction guards, actual callable complexity analysis, full regression and an installed full compile. The dated results below distinguish completed checks from pending installed qualification.

## Local qualification

The corrected round-trip regression fails with the exact original producer function loaded from the base commit: the displayed JSON projection has no complete evidence address. This proves the projection-to-citation gap, not that an actual model cannot read the original heading. The new producer passes for LF, CRLF and Unicode line separators. Forged times, out-of-range indices and partial quotes still refuse binding. The related suite passes 208 tests; Python 3.10 passes 42. Actual AST and Lizard analysis covers seven changed or new callables, with maximum CCN 3, at most two if statements and at most two nesting levels. Ruff passes. The full standard regression completed with 12,383 passed, 227 skipped and three failures: two obsolete draft-version assertions and one missing new-file CI weight. The version guards were updated and strengthened to compare the actual prior program hash; the new file was weighed by the native shard planner. All affected modules then passed (125 tests), as did 20 tests on Python 3.10. Final AST/Lizard analysis covers nine callables with maximum CCN 3. These combined results are not described as a single green full run. A real gpt-6-luna/medium draft probe returned three exactly bound claims in 7.136 seconds (10,779 input and 443 output tokens); this is one draft, not an installed full compile. Installed full-cycle and final CI qualification remain pending; no full-cycle token improvement is claimed.
