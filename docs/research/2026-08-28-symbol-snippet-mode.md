# Сниппет по имени символа из активного поколения

Дата: 2026-08-28. Пункт `CODE-02` единого бэклога (паритет с
`get_code_snippet` у codebase-memory-mcp; разрыв записан в реестре
2026-08-27).

## Вопрос

Агент спрашивает «покажи `claim_capture`» и должен получить тело определения,
а не путь к файлу. У codebase-memory-mcp это отдельный инструмент
`get_code_snippet` по квалифицированному имени; Graphify отдаёт узлы графа с
контекстом. У llm-wiki режим `symbol` отдаёт связи, но не исходник.

## Ограничение данных, измеренное

Метаданные узла активного поколения несут `path`, `owner`, `signature`, `name`
— номеров строк нет (проверено на живом поколении 2026-08-28). Значит сниппет
восстанавливается из файла по определению, а не по диапазону из графа.

## Решение

Режим `snippet` инструмента `get_architecture` (поверхность не растёт —
прецедент `provenance`). Новый модуль `scripts/symbol_snippet.py`:

1. места символа — `find_nodes` активного поколения (≤5);
2. на каждое место: ограниченное чтение файла (≤1 МиБ), поиск строки
   определения (`def name(`, `class name`, presence по границе слова для
   не-Python), срез блока по отступу с потолком 120 строк;
3. `owner` из метаданных включается в ответ для различения одноимённых.

Отказы именованные: файл не найден/велик, определение не найдено — по месту,
не молча. Детерминированно, без модели.

Заодно оформлен голый `ValueError: Evidence Graph query row ceiling exceeded`,
который режим `symbol` бросал сквозь диспетчер (найдено живым вызовом
2026-08-28): инструмент обязан отвечать именованным отказом, а не
исключением.
