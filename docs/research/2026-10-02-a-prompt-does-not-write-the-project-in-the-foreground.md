# A prompt does not write the project in the foreground

2026-10-02. The owner again reported Claude UserPromptSubmit being killed at its existing five-second timeout. No timeout or resource ceiling is raised. A controlled replay of an actual recorded Claude user message through the installed adapter, with cProfile overhead, took 4.785 seconds: 3.803 seconds were the project follow-up after durable ingress, including 3.271 seconds draining project checkpoints. Admission and the advisory were separately measured at 0.203 and 0.099 seconds. The replay is diagnostic evidence, not an observation of a new native host hook. Its full 2589-byte redacted occurrence, one part, and terminal record were verified.

A zero-wait writer admission did not bound work after admission. A project transaction and several rewrites of the existing 1.3 MB operational state still ran synchronously. The first three regression cases failed on the original implementation: foreground project work happened, worker completion did not apply that work, and a project interruption did not prevent terminal completion.

The fix reuses handler 2 and the existing fenced capture worker. Foreground publication, DLP, anchor/part/input verification, queue registration and prompt advisory remain. The worker preserves complete source and daily evidence, applies the project checkpoint, and only then completes the capture. A project failure propagates through the existing retry boundary. Interruption after project commit replays the same event rather than adding a second checkpoint. No daemon, path, schema, environment contract, runtime root, queue kind, MCP tool or arbitrary numerical budget is added.

The worker reconstructs canonical native envelopes from the verified occurrence and anchor. A host timestamp contributes to the original event identity; an acceptance timestamp does not. Both restore the original occurrence and acceptance time. Generic breadcrumb evidence without a native schema still has no native project event to apply. A claimed native schema must have the exact fields, supported version and lifecycle type, and pass the existing envelope validation; malformed native claims cannot complete capture. Existing earlier terminal records are historical completed captures and are not rewritten or replayed automatically.

Primary sources checked on 2026-10-02:

- [Anthropic Claude Code hooks reference](https://code.claude.com/docs/en/hooks), current command-hook timeout and async contracts. The installed command remains synchronous with its existing five-second host timeout.
- [Python 3.10 subprocess documentation](https://docs.python.org/3.10/library/subprocess.html), process, pipe and timeout boundaries. Detached processing alone does not prove durable acceptance; existing ingress remains foreground.
- [SQLite file locking and concurrency](https://www.sqlite.org/lockingv3.html), rollback-journal locking. Admission wait and the duration of an admitted transaction are distinct; existing FULL/rollback-journal contracts remain.

Raising the timeout hides foreground work. Making the entire hook asynchronous loses the guarantee that acceptance precedes host continuation. Dropping the project checkpoint loses project evidence. Reusing the durable occurrence in the existing worker preserves recovery and removes the admitted project transaction from the foreground. The tradeoff is that project handoff becomes visible when this worker commits; source and daily evidence are written first and are retained if the project step fails.

Verification: the original three cases failed. An earlier related candidate run passed 570 tests with 21 skips. After placing project work after source/daily publication, the final changed worker and hook regressions passed 29 tests, including interruption before and after project commit, native identity/time restoration and malformed native-envelope rejection. Mandatory guards passed 64 tests. Lizard measured all 22 changed/new functions, including nested test callbacks: maximum CCN 4. Ruff and Gitleaks passed. Installed-command measurements are recorded separately after installation. The earlier complete 10862-test regression belongs to c3f91a7, not this change. The separate whole-audit ledger remains open; this change does not certify historical capture completeness, all native event types or the basis of every numerical bound.
