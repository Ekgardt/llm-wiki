# Named secret redaction indexes assignment candidates

Research date: 2026-10-09. The installed full compiler's short non-injecting CPU sample has 80 usable stacks and 19 read errors; named credential substitution is the leaf of 26 usable stacks. This is not a whole-cycle percentage. A saved protected request of 252,948 characters takes 0.0332 seconds in that detector alone. Full native-choice optional-context sizing repeats complete transport protection for 1,858 pages and costs 49.815 seconds. An experiment that excluded unrelated individually verified rows did not improve that cost (50.424 seconds), so its code was removed and diagnostic evidence retained. The shared detector's repeated scan is worth measuring as an aggregate cost; the single-call figure alone was insufficient to dismiss it.

Three independent primary sources checked today:

- Python 3.10 `re.Pattern.match` and substitution semantics: https://docs.python.org/3.10/library/re.html#re.Pattern.match . The project still supports Python 3.10; no new regex dependency or newer-only syntax is introduced.
- Gitleaks v8.30.1's upstream rules: https://github.com/gitleaks/gitleaks/blob/v8.30.1/config/gitleaks.toml . Necessary candidate syntax may narrow expensive verification, but the actual detector and replacement must remain authoritative.
- OWASP validation guidance: https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html . Candidate filtering does not replace semantic validation.

Design before code: cheaply find whole assignment-key starts using the existing key-character class, optional escaped quote, same-line spacing and colon/equal separator grammar. At each candidate start invoke the *unchanged original* credential-value regex with `match(text, position)` and the unchanged `_replace_named_value`. Consume the original full match, even when its callback leaves it unchanged, so nested values retain original non-overlapping substitution semantics. The head is an over-approximation: it does not decide a credential keyword, value, name length or redaction. Only this specific built-in pattern takes the optimized path; other and newly added patterns retain their original `.sub` behavior. Keep the authorization-header detector, entropy detector, custom DLP policy, complete-request boundary and fail-closed errors unchanged. No cache of approval, value, source or policy is added.

Alternatives: more detectors or a replacement regex engine add dependency and compatibility risk; skipping full DLP weakens protection; memoizing growing requests retains large content and requires exact policy identity; context limits lose input; extending the credential-name grammar changes detection semantics. This design adds a candidate scan and retains exact matching as its final decision. The grammar correspondence must be maintained if the built-in key syntax itself changes; unknown patterns are deliberately unoptimized. Differential tests use original substitution as the oracle, including Unicode, escaped quotes, 50/51-character prefixes, nested assignments and unknown patterns.

Causal workload RED before implementation: the existing detector applies its credential regex substitution to 36,031 characters of prose plus one assignment. The new guard requires exact original output with one candidate match, without this expensive whole-prose substitution. The original output differential tests already pass, proving this is a work defect rather than missing expected redaction. Qualification remains pending: differential suite, related protection/capture tests, Python 3.10, actual complexity, real saved-request equality/timing, full optional-context sizing, native index update, installation and useful full-cycle accounting.

Candidate checkpoint: causal workload RED is one failure and 19 original-output passes; after the change all 20 tests pass, including 2,000 seeded mixed-grammar comparisons and the unknown-pattern fallback. Expanded protection/capture/compile checks pass 97 tests. Actual AST/Lizard checks of the entire branch since installed 0ac0801f cover 66 callables, maximum CCN 5, no excess if count or nesting; Ruff passes for scripts and tests.

Actual saved protected request: 253,292 characters, digest 269f25341aeae7ea224ab40b3771528f4e7e30597aa0f2827eb08d28b0768ce1, exactly equal redacted output; original named substitution took 0.034817 seconds, indexed matching 0.028065 seconds. Full optional-context sizing after this change took 42.627 seconds for 1,860 current pages versus the earlier candidate's 49.815 seconds for 1,858. These are sequential observations while the installed compiler updates context and shares CPU; they are not a controlled full-cycle speedup. The native-choice path still costs more than the old native no-choice byte estimate. No optimality, full-cycle token saving or installed health is established by these component checks.
