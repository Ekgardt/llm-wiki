# Два стенда, которые оценивают отказ — 2026-09-06

Пункт 7 бэклога: «мерить на стенде, который отдельно оценивает отказ».
LongMemEval считает молчание ошибкой, поэтому каждая наша цифра занижает ровно
то, ради чего система построена.

## RefusalBench

Muhamed и др., arXiv:2510.10390, EACL 2026. Два набора:

| набор | строк | надо ответить | надо отказать | лицензия |
|---|---|---|---|---|
| NQ, один пассаж | 1 600 | 536 | 1 064 | Apache-2.0 |
| GaRAGe, десять пассажей | 1 506 | 450 | 1 056 | CC BY-NC 4.0 |

Шесть видов порчи контекста, три степени: неоднозначность, противоречие,
несоответствие уверенности, ложная предпосылка, несоответствие уровня
детализации, отсутствие сведений.

Заявление авторов, ради которого стенд и сделан: точность отказа падает ниже
50% на многодокументных задачах, и ни размер модели, ни удлинённое
рассуждение этого не чинят.

## LIT-RAGBench

Itai и др., arXiv:2603.06198. 114 вопросов, написанных людьми, пять
способностей: интеграция, рассуждение, логика, таблицы и отказ. **Шестьдесят
из 114 — отказ**: контекст обрывается, противоречит себе или состоит из одних
обманок. Есть и разбор избыточного отказа, а не только недостаточного.
Вымышленные сущности, чтобы ответ нельзя было знать заранее.

## Как запускается

Ни одного нового стенда. Обе выборки переводятся в ту же форму вопроса, что
читает существующий прогон:

```
uv run python benchmark/refusalbench_data.py
uv run python benchmark/litragbench_data.py
uv run python benchmark/run_longmemeval.py \
  --dataset cache/benchmarks/refusalbench/refusalbench-nq-questions.json \
  --sample 200 --seed 101
```

Строка, на которую надо отказать, получает суффикс `_abs`, и разделение на
отказ и ответ, которое подсчёт уже делает, работает без единой новой строки.

## Что этот перевод меняет в стенде — сказано прямо

Оба стенда отдают генератору контекст готовым. Мы кладём контекст в хранилище
и даём извлечению его найти, потому что наш генератор читает только те куски,
которые произвело наше извлечение, и честного обхода тут нет.

Значит у отказа появляется вторая причина: контракт отверг испорченный
контекст — это то, что стенд меряет; или извлечение вообще не подняло пассаж —
это не оно. Прогон пишет `answer_retrieved` по каждой строке, поэтому две
причины различимы и должны докладываться отдельно. Если вторая окажется
заметной, это само по себе результат.

Для LIT-RAGBench обманки (`negative_chunk_list`) кладутся в хранилище тоже:
корпус, где лежит только ответ, — не задача.

## Правило решения, объявленное до прогона

Три величины, каждая отдельно:

1. **Доля правильных отказов** — из строк, где отказ обязателен, сколько
   промолчали. Сравнивать с опубликованными: авторы RefusalBench сообщают,
   что у 30 с лишним моделей она ниже 50% на многодокументных.
2. **Доля избыточных отказов** — из строк, где ответ обязателен, сколько
   промолчали. Это цена нашей политики, и до сих пор мы её не мерили.
3. **Доля отказов, вызванных извлечением** — из отказов те, где
   `answer_retrieved` ложно. Это не заслуга контракта, и в его пользу
   засчитывать нельзя.

Арм считается выигравшим, только если первая величина растёт больше, чем на
разброс стенда, а вторая при этом не растёт.
