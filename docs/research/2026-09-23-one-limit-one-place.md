# One limit, one place

Dated 2026-09-23. The owner asked for the legacy to be cleared and for every limit in the
system to be checked for justification and duplication. This note covers the inventory,
the worktrees left behind by finished agents, and the limits that are duplicated. The
legacy code paths (v2 queue and coordinator readers, the legacy FTS index) get their own
note, because removing them changes what an install builds.

Files: `scripts/bounded_io.py`, `scripts/pinned_download.py`, `scripts/install_pyright.py`,
`scripts/install_language_server.py`, `scripts/evidence_graph.py`, `scripts/trace_ingest.py`,
`scripts/generation_catalog.py`, `scripts/knowledge_extractor.py`, `scripts/project_extractor.py`,
`scripts/memory_state.py`, `scripts/flush_memory.py`, `scripts/integration_adapter.py`,
`scripts/rebuild_memory_index.py`, `scripts/compile_memory.py`, `scripts/session_start_context.py`,
`scripts/user_prompt_capture.py`, `scripts/archive_sessions.py`, `scripts/doctor.py`,
`tests/test_one_limit_one_place.py`, `docs/LIMITS-2026-09-23.md`,
`docs/research/2026-09-23-one-limit-one-place.md`.

## What was found

- `scripts/` defines 657 module-level numeric limits. 36 names are defined in more than one
  module; 15 of those carry the same value in every module, the other 21 the same name for
  different bounds. 303 limits carry no comment within four lines, and 233 of those are
  named in no document either (`docs/`, `CHANGELOG.md`). The inventory is
  `docs/LIMITS-2026-09-23.md`, generated by `tmp/limits_inventory.py` over the work tree.
- Two of the same-name pairs bound the same file with different numbers. Doctor reads the
  hook configuration under `MAX_CONFIG_BYTES = 64 KiB` while the installer writes and
  validates it under 2 MiB (`installer_config`, `integration_hook_config`); doctor reads a
  generation's `manifest.json` under `MAX_MANIFEST_BYTES = 256 KiB` while the catalog that
  writes it allows 1 MiB. A file the writer accepts can be one the checker calls unreadable.
- The 64 KiB I/O chunk exists six times under five names (`COPY_CHUNK_BYTES` twice,
  `IO_CHUNK_BYTES` twice, `HASH_CHUNK_BYTES`, `CHUNK_BYTES`); the two archive installers
  share four archive bounds and the network timeout by copy; the two extractors share
  `MAX_SOURCES` and `MAX_RECORDS`; the capture intent bound, the index bound and the hook
  lock timeout are each defined twice. `archive_sessions.DEFAULT_RETENTION_DAYS = 90`
  cites the contract's ninety hot days in its comment and does not read
  `DEFAULTS.archive_hot_days`, which is that contract.
- 26 worktrees beside the checkout and 19 `worktree-agent-*` branches remain from finished
  agents. `git cherry` finds no commit without a patch-equivalent in `work-rounds` for 17
  worktree branches and 15 agent branches; for the other 9 worktree branches every file
  their non-equivalent commits added exists in `work-rounds` (the equivalence broke on
  conflict resolution during the merges). None is dirty. Four agent branches are different:
  their commits added `scripts/preflight_merge.py`, `benchmark/review_flush_labels.py`,
  `tests/test_export_credential_evidence.py` and a research note of 2026-08-26 that exist
  nowhere in `work-rounds` — subagent deliverables that were never merged. They are kept
  and named here for the owner.

## Practice on this date

- "Every piece of knowledge must have a single, unambiguous, authoritative representation
  within a system" — the DRY principle as Hunt and Thomas state it
  ([The Pragmatic Programmer, 20th anniversary edition](https://pragprog.com/titles/tpp20/the-pragmatic-programmer-20th-anniversary-edition/)).
  A bound copied into a second module is the case the principle names: the two copies
  drift, and the one that drifts is the checker.
- Git's own guidance for a linked worktree whose branch is merged is to remove it and
  prune ([git-worktree(1), `remove` and `prune`](https://git-scm.com/docs/git-worktree)).

## The decisions

1. **A shared bound has one owner and the other modules import it.** The 64 KiB chunk is
   `bounded_io.IO_CHUNK_BYTES`; the archive and download bounds live in `pinned_download`;
   `project_extractor` imports the extractor bounds from `knowledge_extractor`;
   `trace_ingest` imports `MAX_NODE_FILTER` from `evidence_graph`; `memory_state` owns
   `MAX_CAPTURE_INTENT_BYTES` and `HOOK_STATE_LOCK_TIMEOUT`; `rebuild_memory_index` owns
   `MAX_INDEX_BYTES`; `archive_sessions` reads `DEFAULTS.archive_hot_days`. Doctor reads
   the hook configuration and the generation manifest under the writers' own bounds. Module
   attributes keep their names, so nothing that imports a name breaks.
2. **A structure test holds the line.** A limit name defined in two modules with the same
   value is a duplicate and fails the test; the same name with different values is allowed
   only with a comment, which is what the 21 remaining pairs get or already have.
3. **The undocumented limits are listed, not invented.** `docs/LIMITS-2026-09-23.md` names
   every limit without a recorded reason, per module. A reason is added only where a
   measurement or a research note states it; the rest stay listed as open, because a
   comment written today from nothing would be the fabrication rule 3 forbids.
4. **The finished worktrees and their branches go.** The 26 worktrees and 15 agent branches
   that are integrated and clean are removed; the four agent branches holding unmerged
   deliverables stay until the owner decides.

## Result

After the change the work tree defines 637 limits; 21 names are shared across modules, every
one with a different bound and a comment saying which; 218 limits carry no comment and 178 of
those are named in no document — listed in `docs/LIMITS-2026-09-23.md`.
`tests/test_one_limit_one_place.py` passes and refuses a new copy.

## Cost, by rule 4

Imports replace constants; no runtime path changes. The two doctor bounds grow to the
writers' sizes, which bounds one read each at 2 MiB and 1 MiB.
