# A rejected draft is not evidence of source no-content

Research and qualification date: 2026-10-07. Scope: internal automatic compiler behavior, Python 3.10-compatible. No provider, environment, path, receipt schema or runtime contract changes.

The previous compiler validated an operation's physical evidence, asked the critic to review it, removed rejected operations and accepted the remainder. An empty remainder could enter the accepted-plan cache. Publication then derived `no_durable_content` for source descriptors without accepted evidence. Rejecting a proposed generalization does not establish that the original project episode contains no durable fact.

A preserved real draft and critic response reproduced the unsafe empty-plan acceptance on their original immutable seven-source capture. This replay made no inference calls or publication. A separate public fixture uses neutral project facts, rather than private source text. The original fixture fails four source-completion assertions; direct empty drafts, distinct facts sharing evidence and invalid-evidence refusal remain controls.

The current boundary rejects the entire draft when a fully reviewed operation belonging to the current batch receives `drop`. The existing validation-error path remains visible and uses the existing retry and caller-deadline contracts. No rejected operation is restored, rewritten, silently discarded or turned into a no-content receipt. In a mixed pass/drop result, the source remains unresolved; the compiler does not publish the accepted subset and pretend the other source work was completed. Critic responses naming unrelated slugs do not establish rejection of the current operations; the existing missing-verdict check still requires a verdict for every current operation.

The unused operation-filtering helper is removed. Source and target snapshots, physical hashes and spans, claims, immutable decisions, DLP, ordinary receipt authority and publication guards remain unchanged. Draft v15 explicitly retains durable evidenced project facts in their source scope and prohibits invented reusable rules. Critique v6 and the draft program identity invalidate accepted cache entries produced under the previous behavior. Normalization is unchanged.

## Research and alternatives

Three independently maintained primary sources were checked on the research date:

- [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs): constrained shape does not eliminate mistakes in generated content. This is an API capability reference, not proof of native constraints in the installed Codex prompt-schema route.
- [OWASP LLM05: improper output handling](https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/): model outputs remain untrusted and require downstream validation. A critic result is not a source-work completion certificate.
- [W3C PROV-DM](https://www.w3.org/TR/prov-dm/): derivation and entity identity distinguish the source from an activity's output. The design inference here is that rejection of one derived output must not be treated as proof that its source has no useful content. The 2013 recommendation is a provenance reference, not an LLM completeness oracle.

Keeping the filtered subset is cheaper but can irreversibly close the wrong source work. Accepting the rejected generalization would bypass the critic. Automatically rewriting a supported project fact from a rejected operation would invent a semantic repair mechanism. New persistence or a new reviewer response format would expand this change's scope. The selected internal fail-closed boundary is the smallest correction that preserves the existing evidence and receipt contracts.

## Costs and limits

The full prepared source and selected context remain intact. A concise instruction preserves the previous durability criterion without unnecessarily expanding the prompt. Complete required-context fixtures must still fit their existing budgets; no budget is raised.

A rejected draft can now remain pending and consume the existing retry allowance. This is a correctness tradeoff, not demonstrated token savings. A direct empty draft still follows the existing no-op path without a critic; that behavior is not a universal proof of semantic completeness. Existing context or matching evidence alone is not proof that two claims are equivalent. Distinct supported facts sharing evidence must remain admissible.

The preserved artifact replay is not a new useful model cycle, current-source publication or completion of the audit. Earlier replay-operator constructor and artifact-decoding failures are retained separately and excluded from the actual RED/GREEN proof. The original default planning budget, output reservation, safety margin, full-wire capacity and completeness questions remain open.
