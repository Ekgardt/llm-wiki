# Связка код⋈решение⋈сессия: «почему этот код такой?» одним вызовом

Дата: 2026-08-28. Пункт `MEM-16` единого бэклога — асимметричная ставка,
одобренная владельцем 2026-08-28.

## Вопрос

Оператор смотрит на символ и спрашивает, почему он устроен так. Ответ живёт в
трёх слоях этого хранилища: место в коде (Evidence Graph), страница решения,
которая его называет, и дневник/запись сессии, которые страница цитирует с
байтовым доказательством. Ни один инструмент не проходит цепочку целиком.

## Что делает практика

- Сообщество ADR прямо называет разрыв: записи решений «often disconnected
  from the actual system artifacts they influence — source code, models»,
  что ограничивает их пользу в анализе влияния и сопровождении
  ([adr.github.io](https://adr.github.io/), обзор tooling там же).
- Восстановление трасс ADR↔код — открытая исследовательская тема
  ([Trace Link Recovery for ADRs, KIT](https://sdq.kastel.kit.edu/wiki/Trace_Link_Recovery_for_Architecture_Decision_Records_(ADRs))).
- Коммерческий ответ 2026 года — Align: решения собираются в запрашиваемый
  граф ([Align Docs](http://docs.align.tech/blog/architecture-decision-records-complete-guide/));
  Archyl связывает ADR с элементами C4-модели
  ([Archyl](https://www.archyl.com/blog/architecture-decision-records-complete-guide)).
  Встраиваемые аннотации (eadlsync, ADR-аннотации в Java) требуют менять сам
  код.
- Мотив 2026 года: «AI coding agents will refactor away reasoning they can't
  see» — рассуждение должно быть читаемо агентом рядом с кодом
  ([DEV Community](https://dev.to/wallacefreitas/architecture-decision-records-adr-documenting-your-projects-decisions-5ac8)).

Никто из перечисленных не доводит цепочку до первоисточника-разговора с
проверяемой цитатой: у них нет слоя сессий. У нас он есть
(`session-evidence-retention-decision`), и цитаты страниц уже проверяются по
байтам (`part-scoped-evidence-decision`).

## Решение

Новый модуль `scripts/provenance_join.py` + режим `provenance` существующего
инструмента `get_architecture` (12-инструментная поверхность не растёт —
прецедент режимов `impact`/`community`). Детерминированный, только чтение:

1. символ → места в коде из активного поколения (`find_nodes`, ≤5);
2. символ → страницы `knowledge/notes/`, называющие его словом (границы
   слова, ≤8 страниц, ограниченное чтение ≤256 КиБ на файл);
3. каждая страница → её процитированные источники (`knowledge/daily/…`,
   `knowledge/raw/sessions/…`, `docs/research/…`, ≤6 на страницу).

Ответ честен о границе: источники поверхностны, повторную байтовую проверку
делает существующий `read_page` — join направляет к нему, а не изображает
проверку, которой не делал.

## Отвергнуто

- Аннотации в коде (eadlsync-путь): меняют сам код и требуют дисциплины на
  каждом коммите; наша связь восстанавливается из уже написанных страниц.
- Новый MCP-инструмент: поверхность заморожена контрактом; режим — прецедент.
- LLM-восстановление трасс на запросе: недетерминированно и дорого; лексика
  по границе слова + существующие проверенные цитаты дают то же без вызова
  модели (линия «Don't Ask the LLM», см. записку 2026-08-27).

## Мера закрытия

Стенд: ≥10 настоящих символов этого репозитория с известной страницей
решения; join обязан вернуть страницу в `pages` и хотя бы один источник — а
базовая линия (grep по имени) не доводит до сессии. Плюс отрицательные:
символ без решений даёт пустой `pages`, не выдумку.
