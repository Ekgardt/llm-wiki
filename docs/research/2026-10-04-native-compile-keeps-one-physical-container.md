# Native compilation keeps one physical container

Design and evidence date: 2026-10-04. Python minimum 3.10; installed 3.12.3.
The owner approved the versioned physical-container proposal before code.
The compatible readers and compiler are installed. The retained actual model
result passed installed-source verification in an isolated adopted v3 vault
with the supported base profile. Installed hybrid retrieval, whole-day
compilation and whole-nightly qualification remain pending.

Eight original user-event JSON lines span existing compiler parts. Their complete
physical literals also exceed the historical v1 schema's 16,384-character bound.
Neither fragment citation nor copying a decoded string under a physical hash is
valid. A verified native selector identifies one complete user logical line;
local code proves its canonical capture and binds the whole original JSON line.
Source boundaries and historical receipts remain unchanged. Only participating
adjacent parts are joined, and only one source per path reaches the model/cache.
All pending part receipts commit together; already committed companions are
verified context and their immutable receipts are preserved.

The existing 32,768 planning window, less output reservation and slack, rejects
all eight measured atomic units: full projected requests are 38,937–40,381 UTF-8
bytes. These are existing byte-based estimates, not reported model tokens,
guaranteed token upper bounds or verified remote context limits. CLI descriptors on this machine report backend
defaults; they do not establish a 32k remote limit. Raising a numeric constant
would invent a new universal capacity and enlarge unrelated prompts. Truncating
or separately receipting an atomic event would lose its required context/proof.

The selected candidate policy keeps the existing target for ordinary units and
optional context. A verified indivisible native unit may declare exactly its
measured mandatory request plus the existing output/slack reservations, if larger.
This is calculated per unit, never a new global numeric cap. The recorded packing
budget must be used by the subsequent request-fit check. Source/page byte
admission, provider checks, DLP and visible backend refusal remain mandatory.
This policy establishes local payload admission, not a promise about a backend's
context capacity. Unknown token counts refuse; backend/model capacity and full
cycle cost require genuine measured calls before installation is accepted.

Historical strict v1 schemas remain unchanged. V2 readers dispatch versions;
unknown versions refuse. Mixed v2 ledgers preserve historical v1 records. Literal
serialization must preserve Unicode byte identity, including NFD; semantic hashes
still use the existing canonical encoder. No new runtime root, database, setting,
daemon or MCP tool is introduced. Historical readers remain needed for retained
pages, archives, undo and live consumers; their removal requires those uses to end.

Sources checked fresh on 2026-10-04:

- [RFC 8259](https://www.rfc-editor.org/info/rfc8259/): JSON string escaping means
  decoded characters and physical JSON byte positions differ.
- [Python 3.10 JSON](https://docs.python.org/3.10/library/json.html): decoding
  yields logical strings; strict canonical validation and byte binding stay local.
- [OWASP prompt injection prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html):
  sources stay untrusted data, with deterministic validation and least privilege.
- [Anthropic token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting):
  count the complete model-specific request; reported counting is itself an
  estimate and tokenizers differ by model.
- [Google token accounting](https://ai.google.dev/gemini-api/docs/tokens): tokens
  and model input limits are model-specific. No Anthropic or Google endpoint is
  used by this candidate merely because its documentation was consulted.

Qualification must include original failing contracts, all eight actual spans,
forged/missing capture proofs, escape/Unicode/repeated-line boundaries, legacy
readers, mixed ledgers, preserved companion receipts, actual callable complexity,
full useful model cycles and the cost of failed attempts. Controlled fixture
publication is not whole-day compilation or complete nightly evidence.

Qualification checkpoint on 2026-10-04:

- All 460 original native user frames and 990 unchanged physical parts are
  recognized. All eight indivisible units admit their complete mandatory-source
  request; this does not verify arbitrary backend context capacity.
- A genuine Codex draft and critique produced one durable page quoting a complete
  native logical line. Its physical citation binds the original 18,902-byte JSON
  container across two original parts. Both receipts name the same committed
  transaction. The model supplied no optional structured claims; this real run
  therefore proves native compilation and citation, while claim/v2 publication
  is qualified separately by controlled transaction and consumer tests.
- Those two actual calls report 45,291 input and 929 output tokens. Reported
  cache reads, 24,576 tokens, are a subset of input. Money and cache writes remain
  unknown. The initial controlled cycle took 73.91 seconds, including source
  restoration and publication; its reporting code then failed while assuming
  every page had an optional claim ledger. Reverification uses the retained
  actual result without repeating paid/model work. Earlier audit calls of
  unknown cost are not silently assigned zero or excluded from audit cost.
- Genuine failing guards detected forged cached frame text, encoding, bounds and
  path; the binder and projection now reprove the canonical source container.
  A previously committed companion is reread under the writer gate and its exact
  receipt hash enters transaction preconditions. Disappearance, corruption and
  an external edit before prepare refuse publication. This is also checked with
  real v3 adoption, not only the legacy test coordinator.
- Invalid, extra-field and noncanonical historical claim ledgers refuse before
  merge. They are never silently repaired while adding a v2 record. Same-source
  v4 manifests require ascending physical part bounds; v3 retains its historical
  ordering. Packing reuses preencoded metadata fragments without changing its
  exact byte accounting.
- The first generation/retrieval attempt exhausted the existing 60-second
  collection clock. A second explicit maintenance qualification uses the
  existing supported fifteen-minute builder window and also deferred: snapshot
  collection took 56.415 seconds and building exhausted the remaining 848.334
  seconds. Search without an active generation then exceeded its collection
  deadline. The exact expensive build stage has not yet been measured.
- A separate supported base installation, with the optional encoder packages
  genuinely absent, built all 22,747 sources in 80.397 seconds and retrieved the
  actual compiled page through lexical search. The retained model result and
  physical citation were reverified without new model calls; the verification
  cycle took 86.986 seconds. This qualifies that base scenario, not the installed
  hybrid profile, the entire problem day, or a complete nightly operation.
- After installation, 79 guards passed against the identical isolated source,
  and actual installed-source revalidation retrieved the retained page in the
  supported base profile. A fresh installed MCP exposed all 12 tools and the
  refreshed code graph returned the new physical binder. Historical readers
  remain required by retained v1 evidence; they are compatible readers, not an
  unqualified fallback around v2 validation.
- An isolated actual installed vector-builder check reused 44,313 rows from
  the seal-verified historical installed parent and encoded 2,067 new rows.
  Vector building took 287.599 seconds; collection plus building took 347.480
  seconds. Three cold diagnostic blocks of 256 actual texts each took
  33.818–36.419 seconds. These are measurements under the observed machine
  load, not a general latency guarantee. Warm-vector qualification does not
  erase the failed cold build or prove catalog activation, hybrid retrieval
  or the whole nightly pass.
- The unchanged breadcrumb/v1 producer NFC-normalizes part text and cannot
  reconstruct some NFD inputs against their original byte digest. A focused
  critic serialization guard isolates already-verified evidence and does not
  misrepresent that producer failure as an end-to-end Unicode success. That
  capture defect remains open.

All qualification artifacts are private local logs; the public source ships
neither the owner's original conversation nor generated memory.
