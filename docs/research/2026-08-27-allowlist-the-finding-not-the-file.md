# Разрешать находку, а не файл, в котором она живёт

Дата: 2026-08-27. Повод: владелец спросил, соответствует ли правилам 2 и 4
первое применение `allow_fingerprints` — 33 отпечатка целых файлов, где любая
правка любого файла снова закрывала экспорт до пересборки политики.

## Вопрос

Как зрелые сканеры секретов оформляют исключения для заведомо ложных
срабатываний (тестовые фикстуры, корпуса атак), чтобы исключение переживало
посторонние правки файла и при этом не ослабляло границу?

## Что делает практика

- **detect-secrets (Yelp)** ведёт baseline-файл: каждая просмотренная находка
  записана хешем самого секретного значения; тревога поднимается только на
  новые находки. Ложных срабатываний с baseline — 0–5 %, против 5–15 % у
  нетюненного gitleaks. Правка соседних строк файла baseline не трогает.
- **gitleaks** пишет `.gitleaksignore` по отпечатку находки (файл + правило +
  позиция) — «suppressions survive rebases»; рекомендация 2026 года — сужать
  allowlist максимально узко и оформлять не-секреты документированным
  исключением, а не постоянной записью.
- Обе схемы сходятся в одном: единица исключения — **находка**, никогда не
  файл целиком.

## Решение для этого хранилища

`DLPPolicy` получает необязательный `allow_finding_fingerprints`: SHA-256
каждого заменённого спана. Спаны читаются с выравнивания входа и его
отредактированной формы (`difflib.SequenceMatcher`, `autojunk=False`), потому
что редактор не отдаёт находки списком. Отказ остаётся закрытым:

- разрешение срабатывает только когда **каждый** заменённый спан назван в
  списке — один новый секрет в разрешённом файле блокирует;
- рассинхрон выравнивания может лишь сдвинуть или укоротить спан — хеш не
  совпадёт и вход останется заблокированным; расширить список рассинхрон не
  может;
- политика без нового ключа сохраняет прежний дайджест байт в байт — уже
  аутентифицированные политики не инвалидируются.

Пересборка — одна команда продукта:
`export_vault.py --write-allow-policy <путь>`; запускает её владелец.

## Что отвергнуто

- **Встроенные пометки в файлах** (`gitleaks:allow`): фикстуры этого
  репозитория — тестовые данные, чьи байты сравниваются в тестах; пометка
  изменила бы сами данные.
- **Разрешение по пути** (`tests/`): настоящий секрет, случайно попавший в
  тест, прошёл бы границу молча. Узость по значению строже узости по пути.
- **Отпечатки целых файлов** (первое применение): ломаются любой правкой —
  дефект сопровождаемости, ради которого и заведена эта записка.
