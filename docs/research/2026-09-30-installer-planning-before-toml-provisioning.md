# Installer planning before TOML provisioning

Research and reproduction: 2026-09-30. Python 3.10 is supported, and install.sh invokes installer_config.py before uv sync provisions project dependencies. Its import of the shared configuration bound reached integration_config_backup and eagerly imported settings, which requires tomli on 3.10. A real bare Python 3.10 failed with ModuleNotFoundError before planning a fresh environment.

The fix imports setting_value only in the existing backup-retention operation. Fresh synchronization planning remains a standard-library operation; actual retention still reads the same operator setting and propagates parsing/configuration errors. No duplicate constant, fallback parser, package installation before planning, new path or environment contract is introduced. Existing-environment selection retains its explicit inexact fallback if neither caller nor selected environment can name the installed choices.

Primary sources checked on the research date: [Python import system](https://docs.python.org/3.10/library/importlib.html) describes module loading; [uv locking and syncing](https://docs.astral.sh/uv/concepts/projects/sync/) describes dependency provisioning and exact/inexact synchronization; [Tomli upstream](https://github.com/hukkin/tomli) documents the external parser for Python before standard-library tomllib. These are separate upstream projects. Alternatives: moving/duplicating the configuration limit merely hides the dependency chain; vendoring a parser duplicates maintained functionality; an extra pre-sync install adds an unnecessary bootstrap dependency step. Loading the actual setting at its operation preserves validation and avoids those alternatives.

A regression executes fresh sync planning in a separate -S interpreter with both TOML parsers explicitly unavailable. It fails on the old eager import, passes on the fix, and checks the selected .venv and locked exact arguments. A real bare Python 3.10 -S invocation also passes. Related installer/configuration/retention tests: 117 passed, 13 skipped; changed functions have CCN 4 and 1, Ruff passed. No model calls or context changes are involved.
