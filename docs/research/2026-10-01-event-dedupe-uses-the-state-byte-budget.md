# Event deduplication uses the state byte budget

Research date: 2026-10-01. CheckpointReducer evicts the earliest observed identity after 257 distinct observations solely because of an inline 256-entry ceiling. A real state save/reload then admits a replay of that event into pending work despite the state remaining below its existing byte budget. The regression reproduces duplicate admission, not proof that this exact replay happened in the installed vault. Native callers and source inspection show production reducer instances are created from bounded state for the existing bounded checkpoint claim window, then persisted through the shared writer.

Remove the independent per-reducer count eviction. Keep the existing 192 KiB state-writer budget and its byte-pressure eviction of disposable reducer caches. That budget's basis is documented in memory_state.py: a state above the health reader's 256 KiB boundary previously blinded health checks; a writer margin leaves room for concurrent bookkeeping. Pending work and journals are not evictable caches. Losing a whole reducer on genuine byte pressure can still admit duplicate work; this change does not promise permanent or exactly-once deduplication. No schema, setting, directory or environment contract changes.

Three independent primary references checked today: [Redis memory eviction](https://redis.io/docs/latest/develop/reference/eviction/), [Python JSON serialization](https://docs.python.org/3/library/json.html), and [OWASP resource consumption](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/). They support controlling actual encoded resources and checking costs; they do not justify an arbitrary identity count. Redis is not a dependency. Alternatives rejected: raising 256 or adding an unmeasured setting keeps duplicated policy; removing the byte budget recreates a known health failure; another database adds unnecessary architecture.

Regression saves/reloads a real state containing 257 observed identities and replays the first through actual pending admission. The old code queues one duplicate. Independent byte-pressure regression retains pending work while evicting oversized cache state. No model call is used on this path; expected full-cycle benefit is removing unnecessary replay work without losing known event identities while the state budget permits them.
