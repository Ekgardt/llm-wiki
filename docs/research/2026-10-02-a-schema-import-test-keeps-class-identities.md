# A schema import test keeps class identities

Research date: 2026-10-02. The full CI shards on Linux Python 3.10/3.14 and macOS Python 3.10 found eight compile claim tests failing with `candidate claim must be normalized`. Focused local compile tests had passed. A compatibility regression test reloaded the claims module twice in the shared pytest process; modules collected earlier retained the old NormalizedClaim class. The next compile created that old class while the index validated against the reloaded class.

Reproduce by running the compatibility test before a real claim publication, with the widened-claim module collected. Move only the compatibility import exercise into a child Python process. It still presents the earlier reliable_memory surface without validate_database_directory, imports the real claims module, rebuilds a real database, and asserts the database exists without a nested run directory. The parent now also asserts its class identity is unchanged. Do not loosen production isinstance checks, patch downstream modules, skip tests or change CI sharding.

Alternatives: reload every dependent module couples the fixture to unrelated production modules; accepting arbitrary similarly shaped claim objects weakens validation; removing the test loses the installed-interface regression. Process isolation keeps the assertions and the consumer identity contract. The child inherits the hermetic test environment, uses the same interpreter and the existing slow-machine deadline.

Primary sources checked: [Python importlib reload](https://docs.python.org/3/library/importlib.html#importlib.reload) documents stale external references and existing instances; [pytest monkeypatch](https://docs.pytest.org/en/stable/how-to/monkeypatch.html) scopes patched attributes but does not restore side effects of module execution; [SQLite database connection scope](https://www.sqlite.org/inmemorydb.html) distinguishes connection and process lifetime, and this test deliberately keeps its real on-disk rebuild rather than substituting a mock. Versions exercised locally: Python 3.12; other platform qualification requires CI after installation.
