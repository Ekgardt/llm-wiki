# Offered source IDs have one output address

Research date: 2026-10-07. Installed route inspected: Codex CLI 0.160.0; compiler baseline 2a36f103, SHA4c3f99bb. The research below records the initial candidate; the later installation and limited real comparison are recorded at the end.

Two retained real draft responses explain the change. The first returned integer IDs 170 and 172 absent from its 113-ID menu. They equal the visible LF locator column of offered IDs 194 and 196. This proves a display confusion, not permission to infer the intended evidence. The next response used a valid offered ID but added quoted_text to source_line and claim. The existing strict validator correctly refused both responses.

The transient address display now labels source_line as the output ID and LF as a display locator. Both exact values, source order, entry times and full raw FILE text remain available. The transient choice schema enumerates the actual offered integer IDs and retains its exact two-field shape. The existing four-field legacy alternative remains supported. The program identity moves to compile-draft/v14. No durable selector, receipt, evidence schema, configuration, model or authority changes.

JSON Schema [enum](https://json-schema.org/understanding-json-schema/reference/enum) restricts a value to the offered set. [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) describes enforced API structured output, which is a different contract from the current CLI adapter. Local exec help advertises --output-schema, but the installed adapter uses _structured_mode/_prompted_system to place this schema in the system prompt. This candidate does not enable that flag or claim a native grammar guarantee. [OWASP improper output handling](https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/) requires downstream validation of untrusted model output. These are three independent primary publishers, read today. The official Codex cookbook fetch failed; it is not used as proof of route behavior.

Alternatives: removing the locator loses a useful address into the unchanged source; copying quotes into the menu previously added substantial duplicate text; guessing the intended ID or deleting extra fields would weaken evidence authority. Merely adding another instruction leaves the proven two bare numeric columns and unrestricted ID schema. Native constrained transport requires separate capability qualification and is outside this patch.

Baseline tests reproduce three failures: the schema accepts both absent locator integers, and the display presents two bare integer columns. Safety controls pass on baseline and candidate: offered IDs are valid, hybrids remain refused, legacy and no-choice schemas remain valid. The existing display decoder changes only its literal regex; ordered timestamp/ID/LF equality and density assertions remain unchanged. Additional Byte and adapter counting tests retain complete optional Unicode context and source bytes.

Cost on the retained delivered 113-ID protected input: local serialized stdin grows from 39,959 to 43,278 UTF-8 bytes, +3,319 bytes. Fresh DLP preserves the exact protected base. The cost arm retains the old base program text to isolate menu/schema changes; its whitespace adapter is illustrative, not the native model tokenizer. A complete source capture must be re-fitted through the common planner; old near-full selected context cannot be assumed to fit. These initial checks did not establish model quality, a full-wire bound or retry/token savings. Existing 32768/4000/1024 planning assumptions and remaining audit scope are not resolved here.

The change was subsequently installed after 232 related tests passed. Eleven focused tests then passed against the exact installed compiler bytes in an isolated checkout. A read-only comparison on one current pending complete unit retained the same source bytes and six full existing context pages. Both arms used only Codex gpt-6-luna with max reasoning, fresh scratch request caches and ordinary validation; neither published Markdown or receipts. All four model calls returned. Baseline input plus output was 52,925 tokens; candidate was 55,838, a 5.50% increase. Cache reads are already a subset of input and are not added again. Baseline accepted no operations after correctly rejecting an unsupported generalization; candidate accepted three specific operations. These different results do not establish equal-quality efficiency or general completeness. In particular, a supported specific fact remained absent from both plans. The audit therefore remains open; rejecting an overbroad draft does not by itself prove that its source has no durable content.
