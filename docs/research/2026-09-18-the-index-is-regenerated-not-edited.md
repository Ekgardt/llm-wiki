# The index is regenerated, not edited

Dated 2026-09-18. The index half of finding M-B5 of the third audit: the contract tells
agents to update `knowledge/index.md` on every important update, and on this vault that
file cannot name the pages they wrote.

Files: `CLAUDE.md`, `AGENTS.md`,
`tests/test_the_index_is_regenerated_not_edited.py`.

## What was found

- `knowledge/index.md` is tracked in the public repository, and `rebuild_memory_index`
  filters it through `published_paths`: a page appears only if `.gitignore` un-ignores it
  by an exact `!` line. Since 2026-09-10 the repository publishes no page, so a fresh
  install and the owner's own vault both have an index that names nothing but the entry
  points. `tests/test_structure.py::test_the_vault_index_and_log_name_only_published_notes`
  holds that line on purpose, and `CLAUDE.md` §2 already states the publication rule.
- Two places in the same file still tell an agent to "update `knowledge/index.md`" as one
  of the things every important update touches (§3 rule 4, and step 3 of "Default behavior
  for new material"). Following that instruction literally means hand-editing a generated,
  tracked, publication-filtered file with the title of a private page — which is exactly
  what the filter exists to prevent, and what the structure test would catch.
- The compile pass already rebuilds the index inside its transaction, and
  `scripts/rebuild_memory_index.py` is the command for doing it by hand. Nothing else
  should write that file.

## Practice on this date

- The project already solved the same problem for the log and wrote the answer down: the
  tracked `knowledge/log.md` is only the template the repository ships, the vault's real
  editorial log is the private `knowledge/log.local.md`
  (`docs/research/2026-09-14-the-vault-log-is-private.md`). The index is the remaining
  instruction that was not brought into line with the one-directory layout.
- A generated file with a hand-editing instruction attached is the classic source of drift:
  "Don't edit this file by hand" is the standard header of generated artefacts precisely
  because the next regeneration silently discards whatever was written there. Here the
  regeneration happens inside every compile.

## The decision

- Rule 4 and the default-behavior list say what is true: the index is regenerated by
  `scripts/rebuild_memory_index.py` (the compile does it as part of its transaction) and
  lists only published pages; an agent runs the rebuild instead of editing the file, and
  the private navigation of a vault whose notes are not published is search
  (`scripts/search_memory.py`) plus the private log.
- No path, environment variable, publication rule or test changes: this is the contract
  text catching up with the behaviour the code and the structure test already enforce.
  `AGENTS.md` is updated in the same commit, byte-identical as required.
