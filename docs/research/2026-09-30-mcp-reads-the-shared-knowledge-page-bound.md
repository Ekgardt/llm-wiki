# MCP reads the shared knowledge-page bound

Date: 2026-09-30. The established knowledge contract declares one 8 MiB ceiling in bounded_io. MCP still refused valid notes above a separate 4 MiB constant, and its freshness digest returned None for the same accepted memory sources. Reproduced with a 4194305-byte page: read_page returned an error before content was read. The regression also requires its complete digest, so freshness cannot silently lose that source.

Both MCP readers and their safe error wording now use the existing MAX_KNOWLEDGE_PAGE_BYTES directly. The separate constant and its unsupported assertion that a large file cannot be a note are removed. Existing over-ceiling refusal, stable no-follow reading, symlink/race guards and secret-safe error handling remain. No new budget, schema, settings or runtime contract is introduced.

Primary references verified today: [Python file metadata operations](https://docs.python.org/3/library/os.html#os.fstat), [MCP tools and schemas](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [OWASP resource controls](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/). These describe validation and bounded resource work, not a mandatory 4 MiB note limit. The actual numeric basis is the already established local contract and its 4.2 MB journal failure, documented in [one page ceiling](2026-09-10-one-page-ceiling-for-every-reader-of-knowledge.md), rather than a claim that upstream selected 8 MiB.

Alternatives: keeping the smaller bound leaves writers and readers inconsistent; removing the shared knowledge bound loses an existing safety/resource boundary; adding a new configurable MCP limit preserves duplicate policy. Reusing the canonical bound solves this reader mismatch. A real isolated whole-page read and hash took 0.036 seconds with 12821422 peak traced bytes for the boundary fixture. This is one operation, not a universal memory guarantee. The API makes no model call and preserves complete bytes. The existing test refusing a page past the shared ceiling remains.

Failed old-limit tests and a corrected test expectation for the public response envelope remain in the qualification logs.
