# Аудит 2026-09-14, второй: ошибки и проблемы всех систем

Второй проход того же дня, по семействам, которые первый не проверял: мои собственные
сегодняшние исправления, безопасность и приватность, целостность данных и гонки,
скорость и расход токенов, установка, платформы и CI. Каждая проверка начинала с
запросов к графу кода (правило 1); находки подтверждены чтением кода и, где можно,
воспроизведением на временных каталогах. Живое хранилище не менялось, провайдеры не
вызывались. Догадки вынесены в конец. Исправлений в этом документе нет: каждое пойдёт
после своего датированного исследования (правило 2).

Важность: **критическая** — ломает систему при обычной работе; **высокая**;
**средняя**; **низкая**.

## 0. Что сломали мои сегодняшние исправления

**0.1. Разбор Python-кода стал в ~100 раз медленнее — высокая.**
`scripts/code_extractor.py:306,318`: `_span` считает переводы строк от начала файла
для каждого узла. На `scripts/doctor.py` (314 КБ, 6 822 узла) 0,019 с стало 1,82 с,
результат тот же; рост квадратичный, срок внутри цикла не проверяется.

**0.2. Старые поисковые индексы перестают проходить свою проверку — высокая.**
`scripts/corpus_snapshot.py:1686,1794`: `valid_from: someday` раньше хранился как
текст, теперь как пусто; значение входит в строку фрагмента, которую проверка
пересобирает. Версия извлекателя не поднята. Разбор даты зависит от версии Python
(3.11 принимает `20260901`, 3.10 — нет).

**0.3. Читатель JSON берёт последний объект, даже если ответ — первый — высокая.**
`scripts/reply_json.py:41`. Проверка противоречий: цитата из проверяемого текста
после вердикта решает вердикт. Сводка эпизодов: пример формата после настоящего
массива даёт 0 уроков, пакет помечается готовым — уроки дня теряются. Незакрытый
глубоко вложенный JSON даёт `RecursionError`, которого вызывающие не ловят.

**0.4. Недельная задача Windows — тот же лимит, не исправлен — средняя.**
`install-scheduled-tasks.ps1:274`: 2 часа, а недельный проход включает ночной
(8 670 с) и проверку противоречий (до 1 800 с).

**0.5. Потеря аренды сообщается позже её истечения — средняя.**
`scripts/lease_renewal.py:50`: при занятой базе сигнал на 32-й секунде аренды в 30 с.
Для аренд очереди второй воркер может начать раньше, чем первый узнает; завершение
всё равно проверяет токен — повторная работа, не порча.

**0.6. Мелкие:** сбой воркера захвата всегда «отложен», включая последнюю попытку,
после которой задача мертва (`capture_diagnostics.py:98`); бюджет сводки 240 с при
убийстве шага на 300 с — запас 60 с вместо принятых 120; `inference_threads.settle`
снимает флаг остановки, даже если поток ещё работает; ошибка CLI теперь несёт до
500 символов вывода модели в stderr (секреты вычищены, остальное нет).

Попытки сломать безуспешны: продление по старому объекту аренды, классификация
ошибок во всех 7 местах, новые продления оград (не воскрешают чужую), длинные ключи
(никто не ищет по тексту ключа), смещения байтов у страниц, читавшихся раньше,
грамматика уровня захвата (решает только первая строка).

## 1. Критические

**1.1. Первое же ночное обновление кода удалит 93 пакета.**
`scripts/self_update.py:100-102` вызывает `uv sync --locked --no-dev` без `--inexact`
и без дополнений. Пробный запуск этой команды на живом `.venv`: «Would uninstall 93
packages» — torch, transformers, sentence-transformers, onnxruntime, numpy, все
tree-sitter. Семантический поиск, переранжировщик и граф кода исчезнут молча. Ещё не
случилось: ни одна ночь не обновлялась. Тесты подменяют эту функцию.

**1.2. Каждый вызов Claude оставляет полную копию приватного запроса вне хранилища.**
`scripts/llm_client.py:1386-1411`: `claude -p` без `--no-session-persistence`. На
диске 11 545 папок `~/.claude/projects/*llm-wiki-provider-*` (~1,3 ГБ) с текстом
запросов и ответов; на них не действуют правила хранения, удаления и резервных копий
хранилища. `scripts/backfill_sessions.py:76-83` сканирует этот каталог без фильтра и
перенёс бы их в `knowledge/raw/sessions/` без вычистки секретов.

**1.3. Отслеживаемый `knowledge/log.md` несёт приватную историю.**
В рабочем дереве 1 696 незакоммиченных строк — полный приватный журнал; `git commit -a`
опубликует его. `scripts/query_memory.py:2441-2443` дописывает туда путь с текстом
вопроса в обход фильтра публикации; правило 4 CLAUDE.md и четыре навыка велят агентам
писать в этот файл; защитный тест ловит только `[[knowledge/notes/…]]`. В публичной
истории `origin/main` остаются 301 заметка и 2 дневника до #19 — удаление на вершине
их не распубликовало (решение о переписывании истории — владельца).

**1.4. Установка без дополнений не может искать.** `corpus_snapshot.py:20` импортирует
`yaml`, `fact_keys.py:30` и `evidence_pruning.py:24` — `numpy` на верхнем уровне, а
базовые зависимости их не ставят. С заблокированными пакетами не импортируются 20
модулей, MCP `recall` падает `ModuleNotFoundError: yaml`. Смоук-тест CI только
перечисляет инструменты. (Смоделировано блокировкой импорта, не чистой установкой.)

## 2. Целостность данных

**2.1. Повторный запуск мёртвой задачи ничем не ограничен — высокая.**
`memory_queue.py:5103-5106, 782-788, 11346-11363`: лимит читает поколение родителя,
копия стартует с 0. Воспроизведено: 4 перезапуска подряд, ни одного отказа.

**2.2. Аренда, истёкшая на последней попытке, оставляет задачу навсегда — высокая.**
`memory_queue.py:11291-11296`: восстановление V3 ставит `ready`, не глядя на попытки;
взять нельзя (попыток 8), перезапустить нельзя (не `dead`). Воспроизведено.

**2.3. Сводка эпизодов записывает одни и те же уроки дважды — высокая (моя правка
2.1 не закрыла).** Идентификатор операции — хэш ответа модели; пакет помечается после
записи; `StateLockTimeout` — подкласс `OSError` и ловится как «день пропущен»
(`episode_consolidation.py:594`); повтор даёт другой ответ и второй блок.
Воспроизведено. Тот же разрыв — при убийстве шага.

**2.4. Ночной ремонт удаляет поколение, которое строит другой процесс — средне-высокая.**
`doctor.py:7258-7275`: недостроенная папка не зарегистрирована и считается сиротой;
ограда ремонта (`doctor:maintenance`) и ограда обновления репозитория не пересекаются.
Воспроизведено: обе аренды выданы, папка удалена.

**2.5. Замок `run/state.json` может впустить двоих — средняя.** `memory_state.py:236-257`:
гонка двух «похитителей» просроченного замка; воспроизведено с подстроенным порядком.

**2.6. Испорченный `run/state.json` заменяется почти пустым — средняя.**
`memory_state.py:110-123, 347-350`: `load_state` отдаёт `{}`, `update_state` сохраняет

**2.7. Сбой посреди удаления поколения оставляет запись каталога навсегда — средняя.**
`generation_catalog.py:2978-2988`: дерево удалено до коммита; каждая следующая

**2.8. `claim` в V3 не восстанавливает истёкшие аренды — средняя.**

**2.9. Восстановление резервной копии в непустое хранилище сливает наполовину —
средняя.** `private_vault_backup.py:1466-1474`: файлы пишутся по одному, первая

**2.10. Событие, доставленное повторно после полуночи, не проходит никогда — средняя.**

**2.11. Разные соглашения о дате у записей сессий — средняя (здесь UTC, не

**2.12. Перезапущенная старая задача flush дописывает блок повторно — средняя (по коду).**

## 3. Безопасность и приватность

**3.1. Записи сессий на двух путях не вычищаются от секретов — средняя.**
`session_evidence.write_session_evidence` (`:247`) не вызывает `redact_secrets`;
хук вычищает до вызова, а отсоединённый flush (`flush_memory.py:1379-1399`) и
`backfill_sessions.py:131` — нет. Воспроизведено с токеном GitHub и ключом AWS. В живом
хранилище 3 из 264 записей содержат строки, которые вычистка изменила бы (не открывались).

**3.2. Индексация репозитория может выполнить команду из его git-конфига — средняя.**
`repository_index._git_text` (`:180-190`) без `-c core.fsmonitor=false`.
Воспроизведено: `touch` из `core.fsmonitor` выполнился при `index_repository()`.
Доступно через MCP `get_architecture` и ночной `refresh-all`; то же в
`cleanup_worktrees.py:176`. `workspace_revision.py:696` и `impact_analysis.py:129`
защиту уже ставят.

**3.3. OpenCode, первый по приоритету, доверяет любому локальному серверу и не
ограничивает инструменты — средняя (по коду).** `llm_client.py:802-812, 1210-1228`.

**3.4. Идентификатор сессии с переводом строки переписывает шапку записи — низкая.**
`session_evidence._frontmatter` (`:175-186`); воспроизведено `type: decision`.

Проверено и чисто: все вызовы моделей идут через DLP; allowlist стенограмм и обход
путей в `read_page`; HTTP MCP только loopback с токеном; нет `shell=True`, небезопасного
YAML или pickle; права на хранилище 700, базы 600.

**4.3. Ручной `doctor --repair` сжигает попытки задач — средняя.** `doctor.py:8394`:

**4.4. Обновление идёт с `origin/work` мимо CI — средняя.** CI запускается для `main`
и PR в `main`; `self_update` не смотрит, прошли ли проверки.

**4.5. Пробелы CI — средняя.** Полные тесты без дополнений: тесты torch и
sentence-transformers всегда пропускаются; переранжировщик не ставится нигде;

**4.6. Низкие:** `uv` зафиксирован ровно на 0.12.3 во всех хуках; systemd-юниты без
ограничения времени.

Проверено и чисто: синтаксис и API Python 3.10; действия CI закреплены по SHA;
кодировки файлов заданы; слияние настроек Claude идемпотентно.

Три прошлые догадки: (а) индексация хранилища без ограды — **подтверждена**, цена —
дубли поколений; (б) `_manual_compile` без таймаута — **частично опровергнута**,

отбрасывания критика и их причины не пишутся нигде — **подтверждена**.

## 5. Скорость и расход токенов

**5.1. Модель эмбеддингов грузится до проверки, есть ли новые фрагменты — высокая.**
`search_memory.py:985` раньше проверки переиспользования (:658): 6,8 с и 1,2 ГБ на
каждое поколение. Каждое поколение пишет `incremental-manifest.json` 11,5 МБ на 329
источников (99 МБ на поколение). Корпус целиком сканируется ночью несколько раз:
`fact_keys` строит снимок и 3–7 с ключует 0 реплик, сборка поколения 1,4–5,7 с, lint 7 с.

**5.2. `claude -p` тянет лишнее на каждом вызове — высокая (не измерено в токенах).**
`llm_client.py:1406`: нет `--tools ""` и `--strict-mcp-config` (CLI 2.1.270 их
поддерживает), поэтому, вероятно, поднимаются пользовательские MCP-серверы и
отправляются описания встроенных инструментов. Замер кода: 27–34 с на тривиальный запрос.

**5.3. Контекст начала сессии ~3 300 символов, заметная часть шум — средняя.**
Блок влияния кода (158 мс, git) пишет «0 символов» и флажит страницы по слову `words`;
«охранные правила» — 54 % блока, обрезаны на 150 символах посреди слова, часть не по
теме; раздел индекса дублирует `@knowledge/index.md` из CLAUDE.md; дневник и журнал
строятся и отбрасываются потолком 4 000; `run/state.json` (55 КБ) читается 4 раза;
обещанный `logs/session-start-last.txt` не пишется из хука.

**5.4. Каждый хук запускает по несколько интерпретаторов — средняя.** Адаптер
(0,10 с импорта) порождает второй процесс-делегат (`integration_adapter.py:477`);
UserPromptSubmit — три. 0,11–0,30 с на событие во временном хранилище (нижняя граница).

**5.5. 956 МБ поколений, никогда не активированных — средняя.** Ночная и недельная
очистка называют их «pending activation» и оставляют.

**5.6. Классификатор захвата платит дважды за одно и то же — низкая.** 3 из 56 решений
совпадают по `chunk_sha256` с другим; решения по дайджесту до вызова не ищутся.

**5.7. Бюджет ответа считает байты как токены — низкая.** `query_memory.py`:
`fixed_tokens = len(bytes)` занижает вместимость для свидетельств в 3–4 раза; схема
JSON — 48 % системного промпта и пересылается на каждом проходе.
