# Полный аудит системы — 2026-09-25

Аудит проведён по установленной системе на этой машине, на коде `295ece8f`
(слияние PR 42, версия 5.0.0). Код читался целиком по пяти областям: захват и
компиляция, надёжность и состояние, поиск и сервер памяти, эксплуатация и CI,
навигация по коду. Живые данные (журналы, базы, заметки, кэши) смотрелись только
на чтение. Ничего в хранилище не менялось.

**Как читать.** «Проверено» — дефект прослежен по коду или воспроизведён.
«Подозрение» — механизм виден в коде, но последствие не доказано на деле.
«Моя регрессия» — дефект внесён исправлениями 24–25 сентября. Пункты внутри
раздела идут от важных к мелким.

## A. Высокая важность

**A-1. Поиск не может отдать четверть заметок.** Проверено: 52 из 209 заметок.
- `read_page` падает с «Evidence resolution failed: operation_failed» (проверено
  вызовом живого сервера на одной из таких заметок).
- Причина: компиляция пишет в страницу блок `## Claims` с JSON вида
  `"reference":"daily:… bytes:…"`. Разбор ссылок на доказательства
  (`evidence_resolver.py:1225-1256`) принимает его за ссылку, не может разобрать и
  отказывает всей странице.

**A-2. Фильтр секретов пропускает самые частые формы.** Проверено.
- `{"api_key": "…"}`, `{"password": "…"}`, `"Authorization": "Bearer …"`, пароль в
  адресе `postgres://user:pass@host`, `AWS_SECRET_ACCESS_KEY=…`, токены `glpat-`
  проходят без изменений. Ловится только `api_key=…` (`secret_redact.py:24-33`).
- Это единственная очистка перед облачными провайдерами, дневным журналом и
  записями сессий. Стенограммы Claude — это JSON, то есть самая частая форма текста.

**A-3. Длинный дневной журнал компилируется не целиком.** Проверено.
- Журнал больше 16 КБ делится на части. Если несколько частей одного дня попадают
  в одну пачку, в модель уходит только первая: повторы отбрасываются по пути файла
  (`compile_memory.py:577-591`). Квитанции при этом пишутся на все части, и
  пропущенный текст больше никогда не компилируется.
- На живом хранилище многочастных журналов 16 из 29, около 4 МБ текста.

**A-4. Через 90 дней уборка сотрёт записи, на которых держатся архивы.**
Проверено. Моя регрессия.
- Уборка истории транзакций, добавленная 24 сентября
  (`markdown_transaction.py:651`), удаляет записи компиляций старше 90 дней. Архивы
  и разбор ссылок на доказательства ищут эти записи (`evidence_resolver.py:503-518`,
  `compile_memory.py:940`).
- Около 18 ноября начнут падать архивирование, `rebuild_index`, восстановление в
  doctor и разбор доказательств.

**A-5. Недельная уборка очереди будет падать целиком каждую неделю.** Проверено.
Моя регрессия.
- Шаг `queue_purge` всегда передаёт `--include-dead`. У 25 «мёртвых» задач захвата
  нет файла завершения, и план уборки падает на первой же
  (`memory_queue.py:10067-10075`).
- С 27 сентября (они перейдут 30-дневный порог) не будут убираться и 49 успешных
  задач. Тест на такой случай отсутствует.

**A-6. Установка с набором `hybrid` потеряла переранжирование.** Проверено. Моя
регрессия.
- До 25 сентября torch приходил вместе с `sentence-transformers`. Теперь набор
  `hybrid` его не содержит, и переранжирование молча выключено
  (`reranker.py:86-93`), хотя документы обещают его по умолчанию.
- При этом установщик всё равно качает 2,27 ГБ весов переранжирования, а doctor
  жалуется, если их нет.

**A-7. Ночное обновление не поставит новые пакеты на других машинах.** Проверено.
Моя регрессия по последствию.
- `self_update` сравнивает имена пакетов буквально: установлен `huggingface_hub`, а
  в описании `huggingface-hub`. Набор `semantic` никогда не считается установленным
  (`self_update.py:262-285`).
- После перехода на ONNX другие установки не получат `onnxruntime`, и поиск по
  смыслу откатится к поиску по словам. Здесь пакеты уже стояли.

**A-8. Установка без дополнительных пакетов каждую ночь помечается как сбойная.**
Проверено.
- Шаг `models` выходит с кодом 2, если `huggingface_hub` не установлен
  (`install_models.py:283-289`). Ночной проход считает любой ненулевой код сбоем, и
  doctor показывает ошибку. Установщик знает, что код 2 значит «не установлено», а
  ночной проход — нет.

**A-9. Doctor при нехватке времени выдаёт ложные ошибки и советует исправление.**
Проверено вживую.
- С бюджетом по умолчанию 5 с: `queue: error`, `claims: error` с советом
  `--repair`, 9 проверок «не завершены». С бюджетом 120 с всё «ok».
- Причина: истечение срока ловится вместе с настоящими ошибками чтения
  (`doctor.py:2119-2122`, `2481-2488`, `3989-3991`). Это видят командная строка,
  инструмент MCP `status` и `sync_memory`.

**A-10. Захват Codex не оставляет ни записи сессии, ни текста для классификатора.**
Проверено по коду.
- Разбор стенограммы понимает только строки `type: user|assistant`. Строки Codex
  (`response_item` с `payload.role`) превращаются в пустоту
  (`session_evidence.py`). Запись не пишется, сбой не отмечается,
  `backfill_sessions` считает такие сессии пустыми.

**A-11. Без провайдера захват за час тратит попытки и теряется.** Проверено.
- `call_llm_result` на любом сбое возвращает None, и это превращается в обычную
  ошибку, а не в «провайдер недоступен». Часовое ожидание не включается: 8 попыток
  проходят примерно за час, потом классификация отбрасывается
  (`flush_memory.py:842-852`). Тест подставляет ответ, которого продукт не даёт.

**A-12. День с партией в карантине больше никогда не предлагается к компиляции.**
Проверено по коду.
- Карантинная партия всё равно пишет хеш дня (`compile_memory.py:4410-4412`), и
  отбор дней пропускает его навсегда без квитанции. Сообщение «ждёт проверки»
  (`:1991`, `:4420`) неправда.

**A-13. Одно совпадение поиска отправляет новое утверждение в карантин, а оно
блокирует всю партию.** Код проверен; связь с живым хвостом — подозрение.
- `contradiction_pipeline.py:461-470`, `compile_memory.py:3118-3127`. В
  `inbox/claims` лежат 102 кандидата, и их ничто не разбирает.

**A-14. Один сложный файл Python замораживает индекс кода репозитория.**
Проверено, воспроизведено.
- Разбор ловит только `SyntaxError`, `ValueError`, `UnicodeError`. Очень длинное
  выражение даёт `RecursionError` или `MemoryError`, и обновление индекса всего
  репозитория падает навсегда (`code_extractor.py:2200-2210`,
  `import_resolver.py:96`, `:217`).

**A-15. Удалённая или переименованная папка верхнего уровня останавливает индекс
кода.** Проверено по коду.
- Обновление берёт список корней из первого индекса (`repository_index.py:1018`,
  `:1140`). Пропавший корень — отказ `detect`, `refresh`, ночного `refresh-all`.
  Новая папка верхнего уровня не индексируется, а `changes` говорит «не устарел».

**A-16. Навигация по коду ломается на `node_modules` и подобных папках.**
Проверено.
- Ревизия рабочего дерева обходит игнорируемые папки и отказывает после 100 000
  записей: 14,8 с работы и ошибка (`workspace_revision.py:1439-1449`). Любой
  TypeScript-проект с установленными зависимостями.

**A-17. `recall` с `grounded=true` через MCP не укладывается в срок и оставляет
висящие вызовы модели.** Утечка проверена по коду; таймаут выведен из кода.
- Бюджет 10 с при круге провайдера 32 с (`query_memory.py:40-46`). Каждый вызов
  запускает новый неограниченный поток без срока (`query_memory.py:176-189`).

**A-18. Предел ночного таймера systemd меньше худшего случая самого прохода.**
Проверено по константе.
- `TimeoutStartSec` 3 ч, худший случай 3,19 ч в автоматическом режиме
  провайдера (`install_control.py:615`). Тест проходит только потому, что тесты
  подставляют провайдер `fake`.

## B. Средняя важность

Захват и компиляция:
- **B-1.** Правки внутри хранилища не записываются хуком инструментов
  (`post_tool_capture.py:296`); для промптов это исправлено 24 сентября, для
  инструментов нет. Проверено: записей об инструментах почти нет с 8 сентября.
- **B-2.** Два модуля захвата подменяют неудачный импорт пустыми заглушками
  (`post_tool_capture.py:40-64`, `user_prompt_capture.py:54-58`). Проверено.
- **B-3.** Вызовы модели для проверки противоречий не могут изменить итог: итог
  всегда «карантин», а частный текст утверждений уходит провайдеру
  (`contradiction_pipeline.py:268-285`, `356-374`). Проверено.
- **B-4.** Один плохой день блокирует всю консолидацию эпизодов каждую ночь
  (`episode_consolidation.py:486-488`, `700-702`). Проверено.
- **B-5.** Проверка перекрытия времени сравнивает метки как текст, и `.500000Z`
  против `Z` ложно считается пересечением (`contradiction_pipeline.py:152-166`).
  Проверено запуском.
- **B-6.** OpenCode: контекст начала сессии, скорее всего, не доходит; у событий
  инструментов пустая цель; каждый простой считается концом сессии и стоит вызова
  модели (`llm-wiki-memory-opencode.js:35-37`, `210-220`,
  `integration_adapter.py:191-192`). Подозрение по форме событий хоста.
- **B-7.** Промпты Claude не проходят `feedback_capture`, у Codex и OpenCode
  проходят (`integration_adapter.py:3457-3465`). Проверено.
- **B-8.** Поиск кандидатов на противоречие молча останавливается на 50 строках
  (`claims.py:1257-1276`). Проверено.
- **B-9.** Недельное архивирование молчит о причинах и останавливается на первой
  ошибке; журналы 2026-04-13 и 2026-04-19 не заархивируются никогда
  (`archive_daily.py:1981-2031`). Проверено.
- **B-10.** Партии эпизодов с нечитаемым ответом отбрасываются навсегда
  (`episode_consolidation.py:376-380`). Проверено.
- **B-11.** Таймаут хука у хоста (5 с) меньше таймаута делегата (10 с), и хост
  убивает захват раньше, чем тот запишет сбой. Расхождение проверено, потери —
  подозрение.
- **B-12.** Почти дубли страниц: 12 пар об одном факте с почти одинаковыми именами;
  в проверенной паре первая создана 7 сентября, вторая 11 сентября. Компиляция не
  находит существующую страницу. Проверено по живым заметкам.
- **B-13.** Устаревшие факты не заменяются: две страницы говорят «холодный поиск
  23 с», сейчас 2,3 с. Проверено.

Надёжность и состояние:
- **B-14.** 25 захватов застряли на 2,5–4 недели без выхода: задачи «мёртвые»,
  намерения «готовы», ничто их не переводит. Проверено по живой базе.
- **B-15.** 42 из 43 записей о сбоях исходников привязаны к хешам, которых больше
  нет, и никогда не очищаются; они навсегда блокируют уборку `run/`
  (`compile_memory.py:4530`). Проверено.
- **B-16.** 117 транзакций в карантине (58 МБ) не имеют пути к завершению
  (`markdown_transaction.py:7541`, `651`). Проверено.

Поиск и сервер памяти:
- **B-17.** Переранжирование под нагрузкой не включается и при этом тратит CPU:
  прерванный запуск не записывает стоимость, поэтому ожидание не разрешается
  никогда (`retrieval.py:251-257`, `2186-2213`). На свободной машине работает
  (проверено: 2–4 с на запрос), под нагрузкой — нет (проверено проверяющим).
- **B-18.** Словесный запасной путь после истечения срока не запускается: он
  получает уже истёкший срок (`mcp_server.py:806-840`). Воспроизведено.
- **B-19.** Ответ говорит «свежий», если изменился `journal.md`/`state.md`
  проекта или удалена заметка (`mcp_server.py:5178-5182`). Проверено.
- **B-20.** Ошибки при сборке конверта ответа обходят защиту и уходят клиенту
  сырым текстом, возможно с путём (`mcp_server.py:5847-5898`). Разрыв проверен.
- **B-21.** Надзиратель сервера памяти упадёт, если файл исчезнет между обходом и
  `stat` при подсчёте отпечатка кода (`mcp_supervisor.py:45-51`) — ровно в момент
  ночного обновления. Подозрение.
- **B-22.** Словесный поиск без поколения требует совпадения всех слов вопроса,
  включая служебные: «почему systemd таймер, а не cron» — 0 результатов
  (`search_memory.py:4001-4012`). Проверено.

Эксплуатация и CI:
- **B-23.** Установленные таймеры systemd устарели (без `TimeoutStartSec`), и никто
  об этом не сообщает. Проверено.
- **B-24.** Итог ночного обновления кода виден только в журнале ночи: «пропущено»,
  «ошибка загрузки», «зависимости устарели» не доходят до doctor. Проверено.

- **B-26.** Документы говорят, что `doctor --repair` пересобирает поколение; это

- **B-27.** Метка `v5.0.0` встанет на коммит позже датированного выпуска, а

## C. Низкая важность

- **C-1.** Установленный хук PreCompact передаёт удалённый модуль
  `precompact_capture.py`; его спасает прокладка совместимости
  (`integration_adapter.py:121-129`). Установщик не обновляет старые хуки.
- **C-2.** Ошибка `claude --help` один раз — и все вызовы процесса идут без
  изоляции (`llm_client.py:1523-1580`).
- **C-3.** Опечатка в `MEMORY_LLM_PROVIDER` молча включает автоматическую цепочку с
  облачными провайдерами (`llm_client.py:670-684`).
- **C-4.** CLAUDE.md §6 говорит, что вызовы без провайдера ставятся в очередь; так
  делает только функция, которую продукт не вызывает. CLI-путь `flush_memory`
  держат живым только тесты.

## Что в порядке

- Все модельные вызовы идут через одну границу DLP, которая закрывается при сбое.
  Порядок провайдеров верный. Вызовы памяти не захватываются обратно.
- Операционные базы без WAL, `BEGIN IMMEDIATE`, соединения закрываются. Владение
  отнимается только у доказанно мёртвого процесса. Нет живых владельцев,
  незавершённых транзакций и сирот в связях.
- Публикация намерений захвата, адопция, чтение стенограмм: ограничено, повторяемо,
  с правами только владельца.
- Ночной проход ограничен по времени, дерево процессов убивается на таймауте.
  Обновление — только перемотка вперёд. CI не имеет `|| true`, `all-green` ждёт
  всех.
- Повторы запуска языковых серверов (5/30/120 с, не больше трёх), маршрутизация по
  расширению, аренда 10/30 с, установщики с проверкой архивов.
- Слияние результатов поиска, границы кэшей, срезы стадий по видам.
- Живые данные: доктор «ok»; ночной проход 25 сентября без сбоев; индекс свежий;
  холодный поиск 2,4 с; переранжирование на свободной машине применяется.
