## Как читать этот документ

Каждый пункт проверялся чтением текущих исходников по ссылкам реестра и по
фактическим путям, а не по описанию в `CHANGELOG.md` или в предыдущем
status overlay. Дополнительно на этом дереве запускались полный прогон тестов,
структурный lint, `doctor.py` и `repair_installed_memory.py --check`.

Проверка ограничена исходниками. Она не доказывает развёртывание, поведение на
чистой машине, прогон удалённого CI и выпуск. Пункты, закрытые удалением
функции, закрыты именно как удаление, а не как реализация.

На этой машине нет установленного runtime: `run/` и `cache/` пусты,
`repair_installed_memory.py --check` сообщает `adoption_state: fresh`, `doctor`
даёт 9 ok / 5 degraded / 1 skipped из-за отсутствующих индексов и планировщика.
Поэтому раздел «подтверждённое состояние установленной копии» из среза
2026-08-12 повторно не проверялся и здесь не переиспользуется.

## 2. Закрыто частично

### OPEN-001, OPEN-007 — резервная копия есть, переноса на новую машину нет

Шифрованный backup личного vault и `run/` реализован через Restic с манифестом
и проверкой при восстановлении. Restore разворачивает данные только в пустой
каталог: публикации проверенного образа в установленный vault через install-
или recovery-контур нет. Экспорт отдаёт только tracked-файлы HEAD, при этом
`docs/EXPORTING.md` продолжает называть его способом переезда на новую машину.

Проверено: `scripts/private_vault_backup.py`, `docs/USER-GUIDE.md:442-462`,
`docs/EXPORTING.md:3`.

### OPEN-004 — установщик требует точный коммит, но выпуска нет

Привязки к тегу `v3.4.0` больше нет: удалённый bootstrap принимает только
40-символьный OID, сверяет `HEAD`, identity репозитория и обязательные файлы,
имена веток и тегов отклоняются. Публиковать нечего: последний тег всё ещё
`v3.4.0`, аудируемое состояние не выпущено, README не закрепляет ни OID, ни
манифест файлов и хешей выпуска.

Проверено: `install.sh:162-182`, `install.ps1:174-200`, `README.ru.md:128-160`,
`git tag`.

### OPEN-005, OPEN-006 — контур установки не владеет кодом, зависимостями и конфигами Claude и Codex

Есть манифест, транзакция, resumable-установка, rollback и uninstall. Во
владении только профиль, пользовательское окружение, планировщик и фрагменты
хуков Cursor и Antigravity. Исходный checkout, venv с зависимостями, настройки
Claude, хуки Codex и плагин OpenCode остаются вне манифеста: повторный запуск
установщика не обновляет код, а uninstall и rollback их не восстанавливают.

Проверено: `scripts/install_control.py:4386-4402,4643-4654`,
`install.sh:237-244`.

### OPEN-002, OPEN-003, OPEN-009 — граница одна, защита ограничена известными шаблонами

Все первичные вызовы модели идут через `call_candidate`: политика загружается,
prompt и schema очищаются, ответ проверяется до возврата, ошибка политики или
сканера блокирует передачу. Durable-публикация страниц модели перепроверяет
точные байты перед записью. Ограничение: детектор — регулярные выражения и
энтропия, а не полноценный DLP, и очистка убирает секреты, но не приватное
содержимое страниц. Локальный режим принимает только literal-loopback Ollama и
честно сообщает `external_runtime_unverified`; доказать, что внешний сервер
запущен без облака, система не может.

Проверено: `scripts/llm_client.py:145-153,266-355`,
`scripts/model_dlp.py:113-164`, `scripts/markdown_transaction.py:6406,6467`.

### OPEN-017 — ответ Q&A привязан к цитате, но не к её смыслу

Обычный путь больше не печатает сырой ответ модели: результат проходит проверку
схемы, точное совпадение пути, хеша и границ span, запрет дублей и требование
цитаты у каждого утверждения. Не проверяется одно — что цитата действительно
подтверждает утверждение. Правдивая, но нерелевантная цитата из выданного
набора проходит все шлюзы.

Проверено: `scripts/query_memory.py:335-380,554-560`,
`scripts/evidence_resolver.py:715-745`.

### OPEN-019 — захват молча выключается без переменной окружения

Планировщик закрыт: macOS получает per-user LaunchAgent, Linux — user systemd,
cron остаётся явным деградированным вариантом, окружение передаётся в

Проверено: `scripts/llm-wiki-memory-opencode.js:5-9`, `install.sh:405-430`,
`scripts/install_control.py:508-535`.

### OPEN-020 — опасное удаление убрано, пересмотренного возврата failed-задач нет

`clear-failed` удалён. Очистка теперь export-first, требует манифеста и
захватывает только задачи в состояниях `succeeded` и `cancelled`. Исчерпанные и
failed-задачи хранятся бессрочно: пути с проверяемым манифестом, удалением и
восстановлением для них нет. Это осознанная смена политики, но исходный
критерий не выполнен и нигде не переформулирован.

Проверено: `scripts/memory_queue.py:3838-3861,10837-10870`.

### OPEN-036 — вес авторитетности действует только в лексическом пути

README обещает ранжирование по typed-provenance, и в BM25-путях это так: балл
умножается на вес источника (`user` 1.35, `web` 1.1, `ai-derived` 1.0,

сырые баллы бэкендов в формулу не входят, а dense и reranker авторитетность не
учитывают. Единого измеримого договора о доверии по всем путям нет.

Проверено: `scripts/search_memory.py:835-843,2522,3049`,
`scripts/retrieval.py:757-767`.

## 7. Кроссплатформенные разрывы (найдено 2026-08-18 по CI)

Проверки PR #1 красные не из-за правок этого дня, а из-за платформенных
дефектов, которые на Linux не воспроизводятся. Запуск `32128529944`.

### CROSS-01 — публикация архивов на macOS (закрыто)

Запечатанный каталог переименовывался в готовое имя; macOS возвращает EACCES
на переименование каталога без права записи, а обработчик в этом случае удалял
копию. Закрыто в `6d66aa3` для карантина и раньше для публикации.

### CROSS-02 — state root с `..` ломает Windows (закрыто в CI, открыто в коде)

`LLM_WIKI_STATE_ROOT` в CI содержит `..`. Windows-обходчик каталогов по
дескрипторам отказывается идти через `..`, поэтому падали все тесты, пишущие
дневник. В CI путь теперь нормализуется. В коде остаётся дефект:
`_default_coordinator` в `scripts/markdown_transaction.py:1806` читает
переменную окружения без `resolve()`, в отличие от всех остальных читателей.
Файл даёт 104 замечания гейта, поэтому правка отложена.

### CROSS-03 — LSP на macOS и Windows (открыто)

Около двадцати тестов: `PermissionError: Operation not permitted` на операциях
с деревом процессов, `AF_UNIX path too long` (лимит 104 символа против 108),
расхождение `/private`-симлинков, слишком узкие тайминги. Правка требует
чистки `scripts/lsp_process.py` (92 замечания) и `scripts/pyright_session.py`
(90).

### CROSS-04 — ACL архивов на Windows (открыто)

`archive read-only ACL verification failed`: проверка через `icacls` не
проходит на runner'ах. Затрагивает четыре теста BagIt и `evidence_resolver`.

### CROSS-05 — перф-гейт квалификации (открыто)

`warm_overhead_p95_ms` = 22.9 при пороге 20 на четырёхъядерном runner'е.
Измерить это на данной машине нельзя: нет Node.js, квалификация требует
пары Node 22 + Pyright 1.1.411. Нужно либо оптимизировать фасад, либо
переформулировать, на каком железе гейт обязателен.

### CROSS-06 — таймингозависимые тесты (открыто)

`test_heartbeat_failure_is_bounded_when_transition_lock_is_held` и
`test_query_deadline_removes_index_and_allows_retry` падают на linux py3.10 и
проходят на py3.14 — общая нагрузка runner'а, а не логика.

## 8. Стоимость гейта сложности

Порядок работ определяется не сложностью самих дефектов, а тем, что гейт
проверяет файл целиком. На 2026-08-18 в `scripts/` 92 файла из 110 нарушают
гейт, суммарно 1238 функций с CCN > 5. Любая правка в таком файле требует
сначала привести к норме весь файл. Поэтому закрытие оставшихся пунктов — это
программа рефакторинга, а не серия точечных исправлений.

Приведены к нулю замечаний в ходе этих правок: `session_start_context.py`,
`user_prompt_capture.py`, `post_tool_capture.py`, `secret_redact.py`,
`maintenance_helpers.py`, `scheduled_nightly.py`, `capture_diagnostics.py`,
`tests/test_security_invariants.py`, `tests/test_context_noise.py`.
